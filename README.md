# safeenv

화학 안전·규제 문서를 근거로, **출처가 추적되고 근거가 없으면 답하지 않는** 질의응답 시스템.

MSDS(물질안전보건자료), 국내 화학 법령 조문, 화학사고 사례를 수집·색인하고,
그 위에 인용 기반 RAG 질의응답을 올립니다.

> **현재 상태: 5개 유닛 전부 완료 · 운영 단계**
> 수집·색인(u1) · 인용 답변(u2) · 물질 카드(u3) · 자동 평가(u4) · 계정과 업로드(u5).
> 질의 화면은 `/` 입니다.
>
> 골든셋 30문항 실측 (기준선 385, 2026-09-02):
> **Recall@5 0.967 · MRR 0.766 · 거부 정확도 1.000 · 오거부 0.000**.
> 답변 측 지표(정답률 0.917 · 인용 정확도 0.610 · 충실도 0.958)는 기준선 276 의
> 값으로, 이후 검색·거부 개선이 반영되지 않았습니다 — 재측정 예정.
>
> ⚠️ **답변 생성에는 LLM API 키가 필요합니다.** 기본 제공자는 **Google Gemini
> 무료 티어**이며, 키는 https://aistudio.google.com/apikey 에서 발급합니다.
> 키가 없어도 앱은 정상 기동하고 수집·색인·검색·거부는 동작합니다(BR-02) —
> 질의만 `configuration` 오류를 반환합니다. 아래 [진행 상황](#진행-상황) 참조.

## 관리·사용량 화면은 관리자 전용입니다

계정은 u5 에서 도입됐지만 기존 화면에 소급 적용되지 않아, 2026-09-02 실측에서
관리 화면과 `/api/*` 가 전부 익명 200 이었습니다. B 그룹(B1·B2·B2a·B3)이
이것을 닫았습니다. 아래는 **2026-09-04 실측**입니다 — 실행 중인 컨테이너에
직접 요청해서 받은 응답 코드입니다.

| 경로 | 익명 | 로그인한 일반 계정 | 관리자 |
|---|---|---|---|
| `/api/sources`, `/api/jobs`, `/api/stats` | **401** | **403** | 200 |
| `POST /api/sources/{id}/ingest` | **401** | **403** | 도달함 (실측은 409 — 없는 소스로 확인했습니다) |
| `/admin`, `/admin/*` | **303 → `/login`** | **403** | 200 |
| `/usage` | **303 → `/login`** | **403** | 200 |
| `/documents`, `/history` | 303 → `/login` | 200 | 200 |
| `/`, `/substances` | 200 | 200 | 200 (공개 코퍼스, 의도된 동작 — BR-147) |
| `/healthz` | 200 | 200 | 200 (Docker 헬스체크가 씁니다) |

JSON 은 401·403, HTML 화면은 `/login` 리다이렉트로 갈립니다. 리다이렉트를 따라가는
클라이언트에게는 "인증 실패"가 **HTML 본문을 담은 200** 으로 도착하기 때문에,
JSON API 에서는 리다이렉트를 쓰지 않습니다.

**관리자는 가입만으로는 될 수 없습니다.** 가입 후 CLI 로 승격하는 2단계입니다 —
노출됐을 때 먼저 가입한 사람이 관리자가 되는 것을 막기 위해서입니다.

```bash
# 1. http://127.0.0.1:8300/register 에서 가입
# 2. 승격 (되돌리려면 revoke-admin)
docker compose exec app python -m app.cli grant-admin <email>
```

역할은 토큰이 아니라 요청마다 DB 에서 읽습니다. `revoke-admin` 이 다음 요청부터
적용된다는 뜻이고, 대신 관리 화면 요청마다 SELECT 한 번이 듭니다(B3).

### 그래도 공용 네트워크에 올리지 마십시오

`docker-compose.yml` 의 **`127.0.0.1:` 포트 접두사**는 여전히 필요합니다(NFR-18).
인증이 생겼다고 접두사를 제거해도 되는 것은 아닙니다.

- `/` 와 `/substances` 는 의도적으로 열려 있습니다. 접두사를 제거하면 이것이
  네트워크에 공개됩니다.
- 세션 토큰은 서버 측 폐기 수단이 없습니다. 탈취된 토큰은 최대 12시간 유효합니다(AP-3).
- HTTPS 종단이 없습니다. `COOKIE_SECURE` 는 기본 꺼짐이고, 평문 구간에서는
  세션 쿠키가 그대로 보입니다.

| 항목 | 값 |

## 빠른 시작

```bash
# 1. 환경 변수 준비
cp .env.example .env
#    최소한 POSTGRES_PASSWORD 를 채우십시오. 없으면 기동하지 않습니다.

# 2. 바인드 마운트 디렉터리 생성 (권한 문제 예방)
mkdir -p data/originals logs

# 3. 기동
docker compose up -d

# 4. 확인
docker compose ps
open http://127.0.0.1:8300
```

기동 순서는 `postgres`·`redis` 준비 → `migrate` 완료 → `app`·`worker` 입니다.
마이그레이션은 일회성 `migrate` 컨테이너만 실행하므로 경합이 발생하지 않습니다.

## 코퍼스

`data/originals/` 에 **수집한 원본 82건이 함께 들어 있습니다** (법령 JSON 9 ·
물질 API 레코드 49 · MSDS PDF 12 · 사고 사례 12, 약 13MB). 클론한 뒤
공공 API 인증키 없이도 **재색인만으로 전체 코퍼스를 복원**할 수 있습니다 —
원본 보관은 파싱 규칙이 바뀌어도 재수집하지 않기 위한 설계입니다(FQ-8=A).

```bash
docker compose exec app python -m app.cli reindex --scope all   # 약 35분
```

수집 원본은 공개 자료입니다(법령 조문 · 제조사가 공개 배포하는 MSDS ·
공공데이터 사고 사례). 각 출처의 이용 조건은 `config/sources.yaml` 의
`policy_status` 와 `aidlc-docs/` 에 기록돼 있습니다.

## 수집 실행

공공 API 인증키가 있어야 실제 수집이 동작합니다. 키가 없어도 **앱은 정상 기동**하며,
해당 소스의 수집만 명확한 오류로 실패합니다.

```bash
# 소스와 인증키·정책 상태 확인
docker compose exec app python -m app.cli sources

# 수집 실행 (동기, 큐 없이)
docker compose exec app python -m app.cli ingest --source ncis_substance
docker compose exec app python -m app.cli ingest --source law_api --since 2024-01-01

# 색인 현황
docker compose exec app python -m app.cli stats

# 보관된 원본으로 재색인 (재수집 없음)
docker compose exec app python -m app.cli reindex --scope all
```

화면에서도 실행할 수 있습니다: `http://127.0.0.1:8300/admin/sources` → **수집 실행**

**정책상 차단된 소스는 버튼이 비활성화되며, 우회 실행 수단을 제공하지 않습니다.**

## 화면

| 경로 | 내용 |
|---|---|
| `/` | **질의 — 문장 단위 인용, 근거 부족 시 거부** (u2) |
| `/substances` | **물질 안전 카드 — 항목별 출처, 결측은 "정보 없음"** (u3) |
| `/usage` | **LLM 사용량 — 호출·토큰·비용·캐시 적중률** (u2) · 관리자 전용 |
| `/login`, `/register` | 계정 (u5) |
| `/documents` | **내 문서 — 업로드·삭제·재색인, 소유자 격리** (u5) · 로그인 필요 |
| `/history` | 내 질의 이력 (u5) · 로그인 필요 |
| `/admin` | 대시보드 — 시스템 상태, 문서·청크·물질 수, 최근 작업 · 관리자 전용 |
| `/admin/sources` | 소스 목록 — 정책 상태, 인증키 설정 여부, 수집 실행 · 관리자 전용 |
| `/admin/jobs` | 작업 목록 — 상태·진행률 필터 · 관리자 전용 |
| `/admin/jobs/{id}` | **작업 상세 — 항목별 성공/건너뜀/실패와 그 사유** · 관리자 전용 |
| `/healthz` | 헬스체크 (app / db / queue / worker) |
| `/docs` | OpenAPI 문서 |

작업 상세 화면이 u1 의 핵심입니다. 1,000건 수집에서 20건이 실패했을 때
**무엇이 왜 실패했는지**를 화면에서 진단할 수 있어야 부분 실패 처리가 의미를 갖습니다.

질의 화면(u2)에서 지켜지는 규칙 세 가지:

- **인용 없는 문장은 화면에 나타나지 않습니다.** 예외 없습니다.
- **근거가 부족하면 답하지 않고**, 대신 직접 확인할 원문 링크를 줍니다.
- **제거된 문장은 개수를 밝힙니다.** 답변이 완전해 보이게 만들지 않습니다.

스트리밍 중 나타나는 문장에는 **인용 배지가 붙지 않습니다.** 그 텍스트는 아직
근거 검증을 통과하지 않았고, 곧 철회될 인용을 먼저 보여주면 사용자가 그것을
읽고 신뢰하기 때문입니다.

## 설계상 주목할 결정

**섹션 = 청크.** MSDS 16개 섹션과 법령 조(條)는 이미 의미 단위입니다.
고정 크기 윈도우를 씌우면 이 구조와 "제12조" 같은 자연스러운 인용 단위를 함께 잃습니다.
크기를 초과할 때만 문단 경계로 나누고, 중첩은 두지 않습니다.

**파싱 실패 ≠ 데이터 손실.** MSDS 섹션이 8개 미만만 인식되면 `unstructured`로 표시하고
문단 단위로 색인합니다. 섹션 메타데이터를 잃는 것은 감수하지만 문서를 잃지는 않습니다.

**출처 없는 문서는 색인하지 않습니다.** `source_url`과 `doc_type`이 없으면 저장을 거부합니다.
추적 불가능한 청크는 없는 것보다 나쁩니다 — 다음 유닛이 그것을 인용하게 됩니다.

**오류 3분류.** `transient`(재시도) / `permanent`(재시도 안 함, 다음 실행에서는 재시도) /
`policy_blocked`(재시도도 우회도 안 함). 2분류로는 세 번째를 표현할 수 없습니다.

**벡터는 별도 테이블.** `chunk_embedding`을 분리해 두면 임베딩 모델 교체 시
새 벡터를 병행 적재한 뒤 전환할 수 있어, 재색인 중에도 검색이 계속 동작합니다.

**후행 유닛 확장 지점 선반영.** `chunk.owner_id`(u5), `substance_synonym`(u3),
검색 메서드의 `scope` 필수 인자(u5)가 지금은 쓰이지 않지만 이미 존재합니다.
나중에 추가하면 수십만 청크에 대한 `ALTER TABLE`과 전체 재색인이 발생합니다.

## 개발

```bash
# 의존성 (ML 스택은 선택 — 단위 테스트는 필요 없음)
pip install -e ".[dev]"

# 단위 테스트 — 네트워크·DB 불필요
pytest

# 린트
ruff check app tests
```

임베딩 라이브러리가 없으면 결정론적 해시 스텁으로 자동 대체되어 파이프라인이 끝까지 동작합니다.
**의미 있는 유사도를 주지 않으므로** 실제 검색 품질 평가에는 사용할 수 없습니다 (로그에 경고 출력).

초기 색인에 최대 8시간이 걸립니다. `docker compose down -v` 전에 반드시 백업하십시오.

```bash
./scripts/backup.sh                                   # ./backups/ 에 덤프 생성
./scripts/restore.sh ./backups/safeenv-20260820-1200.dump
```

## 진행 상황

| 유닛 | 내용 | 상태 |
|---|---|---|
| **u1** `ingestion-index` | 수집 · 문서처리 · 색인 · 운영 화면 | ✅ **완료** |
| **u2** `rag-qa` | 하이브리드 검색 · 인용 답변 · **근거 부족 시 거부** · LLM 추적 | ✅ **완료** |
| **u3** `substance-card` | 물질 안전 카드 (항목별 출처 · 결측 고지) | ✅ **완료** |
| **u4** `evaluation` | 골든 QA 셋 자동 평가 · 회귀 감지 · 기준선 승격 | ✅ **완료** |
| **u5** `account-upload` | 계정 · 사용자 문서 업로드 · 소유자 격리 | ✅ **완료** |

**운영 단계 진행 중.** 코퍼스 82문서 · 1,712청크 · 물질 49종.
매일 `safeenv evaluate --retrieval-only`(LLM 0회, 수십 초)가 검색 회귀를 잡고,
기준선 승격은 사람이 합니다(BR-129). 운영 문서는 `aidlc-docs/operations/`.

설계 문서 전체는 `aidlc-docs/` 에 있습니다. 비즈니스 규칙은
`construction/u1-ingestion-index/functional-design/business-rules.md` (BR-01~BR-62, BR-27a·31a)와
`construction/u2-rag-qa/functional-design/business-rules.md` (BR-63~BR-96, BR-86a·92a) 입니다.
u2 의 인젝션 방어 설계는 `construction/u2-rag-qa/nfr-design/nfr-design-patterns.md` (SP-1~9).

## 알려진 제약

| 항목 | 내용 |
|---|---|
| 공공 API 스펙 | 인증키 미보유로 실제 응답 형식 미검증. 어댑터는 `config/sources.yaml` 설정 주도이므로 필드명 수정은 설정 변경으로 가능 |
| MSDS 파싱 성공률 | 실제 PDF 레이아웃 다양성에 따른 실패율 미실측 |
| 스캔 PDF | OCR 미지원. 텍스트가 추출되지 않는 문서는 `permanent` 실패로 기록되고 원본은 보관 |
| 임베딩 성능 | 로컬 모델의 실제 속도·메모리 미실측 |
| **답변 생성** | 실측 완료 — 정답률 0.917 · 인용 정확도 0.610 · 충실도 0.958 (기준선 276). 무료 티어 심판 할당량 때문에 `--full` 1회가 하루 걸린다 |
| **물질 카드 결측** | 물질 49건 중 41건이 7항목 중 6개 결측이다. 원인은 코퍼스이지 코드가 아니다 — 해당 물질의 MSDS 가 없다. **FR-25 가 예상한 상황**이며 화면이 결측 수를 고지한다 |
| **FR-26 UN·이명** | 출처에 데이터가 없어 5종 중 3종만 동작한다. 검색 화면이 이를 상시 표시한다 |
| **LLM 제공자** | `LLM_PROVIDER=gemini` (기본) / `anthropic`. 전환은 설정 한 줄이다 — `LLMPort` 뒤의 어댑터 교체이며 `app/rag/` 는 제공자를 모른다 (NFR-21) |
| **리랭커** | 기본 OFF(`RERANKER_ENABLED=false`). 켜려면 `docker compose --profile reranker up -d` — 모델 다운로드가 추가로 필요 |
| **인젝션 플래그** | `SP-4` 스캐너는 색인 시점에 동작한다. **기존 청크에는 플래그가 없으므로** 재색인 1회가 필요하다 |
| 거부 임계값 | `REFUSAL_SCORE_THRESHOLD=0.50`. **임계값만으로는 부족하다는 것이 측정으로 확인됐다** — 코퍼스에 없는 물질을 묻는 질문(0.631)이 답할 수 있는 질문(0.627)보다 높게 나온다. BR-73a 가 주제 범위로 따로 거른다 |
| 한국어 키워드 검색 | PostgreSQL 에 한국어 형태소 분석기가 없다. 질의 쪽은 조사 절단, 색인 쪽은 조문 제목 부분일치로 우회한다. 완전하지 않다 |
| **물질 미지목 질문** | 물질을 지목하지 않은 일반 MSDS 질문("보호구는 어떻게 선택하나요?")은 답하지 않고 물질명을 되묻는다. 코퍼스에 없는 물질을 다른 물질 자료로 답하지 않기 위한 대가다(BR-73a) |
