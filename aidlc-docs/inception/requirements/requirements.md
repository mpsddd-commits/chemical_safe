### 성공 기준 (Definition of Done)

- **SC-1**: 공개 데이터로부터 물질 **1,000종 내외**의 MSDS·법령·사고사례가 수집·색인되어 있다
- **SC-2**: 자연어 질문에 대해 **문장 단위 출처 인용**이 붙은 답변이 반환된다
- **SC-3**: 근거가 불충분한 질문에는 **답변을 거부**하고 원문 링크만 제시한다 (환각 차단)
- **SC-4**: 물질명 또는 CAS 번호로 **물질 안전 카드**를 조회할 수 있다
- **SC-5**: 사용자가 업로드한 PDF가 인덱싱되어 본인의 질의 대상에 포함된다
- **SC-6**: **골든 QA 셋 기반 자동 평가**가 실행되어 검색·답변 품질 지표가 수치로 산출된다
- **SC-7**: 모든 LLM 호출의 모델·토큰 수·지연시간·추정 비용이 기록되고 조회 가능하다
- **SC-8**: `docker compose up` 단일 명령으로 전체 시스템이 기동된다

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 데이터 수집 (Ingestion)

- **FR-1**: 공공 오픈 API로부터 **화학물질 기본정보**를 수집한다 — 국문·영문 물질명, CAS 번호,
  UN 번호, GHS 분류(유해·위험성 구분), H(유해위험문구)·P(예방조치문구) 코드 *(Q7=D)*
- **FR-2**: 공공 오픈 API로부터 **국내 화학 관련 법령 조문**을 수집한다 — 화학물질관리법,
  화학물질의 등록 및 평가 등에 관한 법률(화평법), 산업안전보건법. **조·항·호 단위**로 분해 저장 *(Q6=C)*
- **FR-3**: 공공 오픈 데이터로부터 **화학사고 사례**를 수집한다 — 사고 일시·장소·물질·원인·피해·조치 *(Q6=C)*
- **FR-4**: 공개된 **MSDS PDF 문서**를 내려받아 파싱한다. MSDS **16개 표준 섹션** 구조를 인식하여
  섹션 단위로 분해한다 *(Q7=D)*
- **FR-5**: 모든 외부 수집 전 **robots.txt 및 이용약관 정책을 검사**한다. 정책상 차단된 소스는
  수집하지 않으며, 차단 사실과 사유를 기록한다. 정책 우회 경로(헤드리스 브라우저 등)는 제공하지 않는다 *(Q9=A)*
- **FR-6**: 수집 작업은 **비동기 작업 큐**를 통해 실행되며, 작업 상태(대기/진행/성공/실패)와
  진행률을 조회할 수 있다 *(Q23=B)*
- **FR-7**: **증분 갱신**을 지원한다. 문서 콘텐츠 해시 또는 발행일 기준으로 변경을 감지하여
  변경된 문서만 재처리한다
- **FR-8**: 수집 실패 시 **재시도 정책**(지수 백오프, 최대 시도 횟수)을 적용한다.
  개별 문서 실패는 전체 작업을 중단시키지 않으며(부분 성공 허용), 실패 사유가 기록된다

### 3.2 문서 처리 및 인덱싱

- **FR-9**: 수집 문서를 **정규화**한다 — PDF 텍스트 추출, 표 처리, 공백·제어문자 정리,
  문서 유형별 구조 분해(MSDS 16섹션 / 법령 조·항·호 / 사고사례 필드)
- **FR-10**: **문서 구조 경계를 보존하는 청킹**을 수행한다. 각 청크에 다음 메타데이터를 부착한다:
  물질명, CAS 번호, 문서 유형, 섹션 번호·제목, 출처 URL, 발행·개정일, 소유자(업로드 문서인 경우)
- **FR-11**: 각 청크의 **임베딩 벡터를 생성**하여 벡터 저장소에 적재한다 *(Q12=C, Q13=A)*
- **FR-12**: **키워드 인덱스**를 구축한다. CAS 번호, 물질명(국문·영문·이명), UN 번호는
  정확 일치 검색이 가능해야 한다 *(Q14=C)*
- **FR-13**: 인덱싱 파이프라인은 **멱등(idempotent)** 하게 재실행 가능하며,
  임베딩 모델 교체 시 **전체 재색인**을 지원한다

### 3.3 자연어 질의응답 — **MVP 중심 기능** *(Q4=A)*

- **FR-14**: 사용자의 자연어 질문을 접수하고 근거 기반 답변을 반환한다
  (예: "황산을 취급할 때 필요한 보호구와 응급조치는?")
- **FR-15**: **하이브리드 검색**을 수행한다 — 키워드 검색(BM25/FTS)과 벡터 검색을 병렬 실행하고
  순위 융합(RRF 등)으로 후보를 통합한다 *(Q14=C)*
- **FR-16**: 통합된 후보 상위 K건에 **리랭커(cross-encoder)** 를 적용하여 최종 근거를 선별한다 *(Q14=C)*
- **FR-17**: 질의에서 **물질명·CAS 번호 등 엔티티를 추출**하여 메타데이터 필터로 활용한다
  (특정 물질이 지정된 질문은 해당 물질 문서로 검색 범위를 좁힌다)
- **FR-18**: 답변은 **검색된 근거 청크만을 사용**하여 생성한다. 모델의 사전 지식만으로 생성된
  주장은 허용하지 않는다 *(Q16=A)*
- **FR-19**: 답변의 **각 문장에 출처 마커**를 부착한다. 마커 클릭 시 해당 근거의 원문 스니펫이
  하이라이트되어 표시되며, 원본 문서 링크를 제공한다 *(Q15=C)*
- **FR-20**: 검색 결과의 관련도가 **임계값에 미달**하면 답변을 생성하지 않고
  "확인할 수 없음"을 반환하며, 참고 가능한 원문 링크만 제시한다 *(Q16=A)*
- **FR-21**: 생성된 답변에 대해 **근거 지지 여부를 사후 검증**한다. 근거에서 지지되지 않는 문장이
  탐지되면 해당 문장을 제거하거나 답변 전체를 거부한다 *(Q16=A, Q18=C 와 연계)*
- **FR-22**: 질의는 **단발성**으로 처리한다. 이전 대화 내용을 참조하지 않는다 *(Q19=A)*

### 3.4 물질 안전 카드 — **2순위 기능** *(Q5=B)*

- **FR-23**: 물질명 또는 CAS 번호 입력 시 해당 물질의 **구조화된 안전 카드**를 반환한다
- **FR-24**: 안전 카드는 다음 항목을 포함한다 — GHS 분류 및 신호어, H·P 문구,
  물리화학적 성질, 권장 개인보호구, 응급조치 요령, 저장·취급 시 주의사항, 적용 법령 목록
- **FR-25**: 카드의 **각 항목마다 출처 문서와 섹션**을 표기한다. 데이터가 없는 항목은
  추정하지 않고 "정보 없음"으로 표시한다
- **FR-26**: **동의어 검색**을 지원한다 — 국문명, 영문명, 이명(異名), CAS 번호, UN 번호

### 3.5 사용자 문서 업로드 *(Q10=A)*

- **FR-27**: 사용자가 **PDF 문서를 업로드**하면 비동기로 파싱·인덱싱되어 질의 대상에 포함된다
- **FR-28**: 업로드 문서는 **업로드한 사용자에게만** 검색·조회된다. 타 사용자의 질의 결과에
  노출되지 않는다
- **FR-29**: 업로드 문서의 **목록 조회, 삭제, 재색인**이 가능하다. 삭제 시 해당 청크와 벡터도 제거된다
- **FR-30**: 업로드 시 **파일 검증**을 수행한다 — 확장자·MIME 타입, 최대 파일 크기,
  최대 페이지 수, 악성 파일 차단

### 3.6 인증 및 계정 *(Q22=B)*

- **FR-31**: 이메일 + 비밀번호 기반 **회원가입 및 로그인**을 제공한다. 인증은 JWT로 유지한다
- **FR-32**: 사용자별 **질의 이력**을 저장하고 조회할 수 있다 (질문, 답변, 사용된 근거, 시각)
- **FR-33**: 비밀번호는 **단방향 해싱**하여 저장하며, 최소 길이·복잡도 정책을 적용한다

### 3.7 안전 고지 *(Q17=C)*

- **FR-34**: **최초 진입 시 1회 면책 고지에 동의**해야 서비스를 이용할 수 있으며, 동의 기록을 저장한다
- **FR-35**: **모든 답변에 면책 문구를 상시 노출**한다 — "본 정보는 참고용이며, 실제 취급 시에는
  제조사가 제공하는 원본 MSDS와 안전보건 전문가의 확인이 필요합니다"

### 3.8 품질 평가 *(Q18=C)*

- **FR-36**: **골든 QA 셋(30~50문항)** 을 저장소에서 관리한다. 각 문항은 질문, 기대 답변 요지,
  정답 근거 문서·섹션을 포함한다
- **FR-37**: 평가를 실행하여 다음 지표를 산출한다 — **검색 지표**(Recall@k, MRR),
  **답변 지표**(정답률, 인용 정확도, 거부해야 할 질문의 정확한 거부율)
- **FR-38**: **LLM-as-judge** 로 답변의 **충실도(faithfulness)** 와 관련성을 채점한다
- **FR-39**: 평가 결과를 **이력으로 저장**하고, 이전 실행 대비 지표 변화를 비교할 수 있다

### 3.9 관측성 *(Q25=B)*

- **FR-40**: **구조적 로깅**(JSON)을 수행하며, 요청 ID로 전체 처리 경로를 상관 추적할 수 있다
- **FR-41**: 모든 **LLM 및 임베딩 호출을 추적**한다 — 모델명, 입력·출력 토큰 수, 지연시간,
  추정 비용, 성공/실패 여부
- **FR-42**: 추적 데이터를 **조회하는 화면 또는 API**를 제공한다 (기간별 집계, 비용 합계)
- **FR-43**: **헬스체크 엔드포인트**를 제공한다 (앱, DB, 워커, 큐 상태 포함)

### 3.10 웹 UI *(Q21=A)*

- **FR-44**: **질의 화면** — 질문 입력, 답변 표시, 인용 마커 및 원문 스니펫 하이라이트
- **FR-45**: **물질 카드 화면** — 물질 검색 및 안전 카드 표시
- **FR-46**: **문서 관리 화면** — 업로드, 목록, 삭제, 처리 상태
- **FR-47**: **질의 이력 화면** — 과거 질문과 답변 재열람
- **FR-48**: **운영 화면** — 수집·색인 작업 상태, 평가 결과, LLM 사용량·비용

**FR 합계: 48건**

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능
- **NFR-1**: 자연어 질의의 **첫 응답(스트리밍 첫 토큰) P95 ≤ 5초**, 전체 답변 완료 P95 ≤ 20초
- **NFR-2**: 검색 단계(하이브리드 + 리랭킹)만의 **P95 ≤ 2.5초**
- **NFR-3**: 물질 안전 카드 조회 **P95 ≤ 1초** (구조화 데이터 직접 조회)
- **NFR-4**: 인덱싱 처리량 — 물질 1,000종 초기 색인이 **로컬 환경에서 8시간 이내** 완료

### 4.2 정확성·신뢰성 (안전 도메인 핵심)
- **NFR-5**: **인용 정확도 ≥ 95%** — 답변 문장에 부착된 출처가 실제로 그 내용을 담고 있어야 함
- **NFR-6**: **근거 없는 주장(환각) 0건 목표**. 평가셋 기준 faithfulness 위반 ≤ 5%
- **NFR-7**: 답변 거부 임계값은 **설정으로 조정 가능**해야 하며, 기본값은 보수적으로 설정한다
- **NFR-8**: 데이터가 없는 항목은 **추정하지 않는다**. "정보 없음"이 잘못된 값보다 항상 우선한다

### 4.3 확장성

- **NFR-11**: 비밀번호는 **bcrypt 또는 argon2** 로 해싱한다. 평문·가역 암호화 금지

- **NFR-13**: 업로드 파일은 **웹 루트 외부**에 저장하고, 원본 파일명을 그대로 사용하지 않는다
- **NFR-14**: **LLM API 키 등 비밀값은 환경변수로만 주입**하며, 저장소 커밋 및 로그 출력을 금지한다.

- **NFR-15**: 업로드 문서에 대한 **접근 통제**를 서버 측에서 강제한다 (FR-28)
- **NFR-16**: **프롬프트 인젝션 방어** — 검색된 문서 내용은 데이터로만 취급하며, 문서에 포함된
