# Components — safeenv

**단계**: INCEPTION / Application Design
**작성일**: 2026-08-20
**근거**: `inception/plans/application-design-plan.md` (DQ-1~DQ-19 답변 확정)

> 본 문서는 **컴포넌트 식별과 책임**만 정의합니다.
> 세부 비즈니스 규칙(임계값, 청킹 규칙, 스코어 융합식 등)은 **Functional Design(유닛별)** 으로 이월합니다.

## 0. 컴포넌트 조직 원칙

**패키지 구성** (DQ-1=B) — 기능(도메인) 모듈을 상위로 두고, 각 모듈 내부에서 계층을 분리합니다.

```
app/
  core/           # 설정, 로깅, 예외, 공통 타입          [공용 기반]
  db/             # 엔진, 세션, ORM 모델, 리포지터리       [공용 기반]
  ports/          # 추상 인터페이스 (LLM/임베딩/리랭커/소스)  [공용 기반]
  adapters/       # 포트 구현체                          [공용 기반]
  jobs/           # 작업 상태 추적, 큐 진입점
  ingestion/      # 수집
  processing/     # 파싱 -> 정규화 -> 구조분해 -> 청킹
  indexing/       # 임베딩 적재, 키워드 인덱스
  retrieval/      # 엔티티 추출, 하이브리드 검색, 리랭킹
  generation/     # 프롬프트, 생성, 거부, 검증, 인용
  evaluation/     # 평가
  substances/     # 물질 안전 카드
  accounts/       # 인증, 사용자
  documents/      # 업로드 문서 관리
  observability/  # 사용량·비용 집계
  web/            # 라우터, 템플릿, 정적 파일
```

> **⚠️ DQ-1 적용에 대한 고지**: DQ-1=B(기능 기준)를 적용했으나, 여러 도메인 모듈이 공유하는
> 설정·로깅·DB 세션·포트 정의는 특정 도메인에 귀속시킬 수 없어 `core/`, `db/`, `ports/`, `adapters/`
> **공용 기반 계층**을 두었습니다. 실질적으로는 DQ-1의 **C(혼합)** 에 근접합니다.
> 순수 B를 원하시면 승인 시 알려 주십시오. → 설계 결정 **DD-1**

**계층 규칙**: 상위 계층은 하위 계층에만 의존합니다. 역방향 및 순환 의존은 금지합니다.

| 계층 | 내용 |
|---|---|
| **L4 진입점** | 웹 라우터 / 워커 / CLI |
| **L3 서비스** | 오케스트레이션 (S1~S8) |
| **L2 도메인 컴포넌트** | 수집 / 처리 / 색인 / 검색 / 생성 / 평가 / 카드 / 계정 |
| **L1 포트·어댑터** | 외부 시스템 추상화 |
| **L0 공용 기반** | 설정 / 로깅 / DB / 리포지터리 |

## 4. L2 — 문서 처리 (유닛 u1)

**파이프라인 구조** (DQ-3=A): 각 단계를 독립 컴포넌트로 두고 체인으로 실행합니다.
단계 경계가 곧 **재개 지점**이 되어 부분 실패 복구가 가능합니다.

```
Fetch -> Extract -> Normalize -> Structure -> Chunk -> Embed -> Persist
 C18      C19        C20         C21         C22      C24      C25/C26
```

| ID | 컴포넌트 | 책임 | FR/NFR |
|---|---|---|---|
| **C18** | `FetchStage` | 원본 확보 및 **원본 보존**. 원본 파일 또는 원본 URL을 기록 | FR-4, DD-4 |
| **C19** | `ExtractStage` | PDF·HTML에서 텍스트 추출. **문자 오프셋을 보존**하여 이후 스니펫 역참조가 가능하도록 함 | FR-4, FR-9, FR-19 |
| **C20** | `NormalizeStage` | 공백·제어문자 정리, 표 구조 텍스트화, 인코딩 정규화 | FR-9 |
| **C21** | `StructureStage` | 문서 유형별 구조 분해 — **MSDS 16개 표준 섹션** / **법령 조·항·호** / **사고사례 필드** | FR-9 |
| **C22** | `ChunkStage` | 구조 경계를 보존하는 청킹 + 메타데이터 부착(물질명, CAS, 문서유형, 섹션번호·제목, 출처 URL, 발행일, 소유자) | FR-10 |
| **C23** | `PipelineRunner` | 단계 체인 실행, 단계별 성공/실패 기록, 중간 재개, 부분 실패 허용 | FR-8, FR-27 |

**원문 보존 3계층** (DQ-4=A): `원본 파일/URL` → `추출 텍스트(오프셋 보존)` → `청크`.
인용 스니펫(FR-19)은 추출 텍스트의 오프셋 구간으로 역참조합니다. 청크 전문을 그대로 노출하지 않아
하이라이트 범위를 정밀하게 제어할 수 있습니다.

**구조화 출력 설계 근거** (DQ-8=A): 문장과 근거 ID가 분리된 자료구조로 반환되므로

사후 유사도 매칭(C)은 검증이 확률적이 되어 NFR-5(인용 정확도 95%)를 보장하기 어렵습니다.
