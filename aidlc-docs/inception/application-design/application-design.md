## 2. 설계 개요

### 2.1 한 장 요약

```
[진입점]  WebRouters / Worker / CLI
              |
[서비스]  S1 수집  S2 색인  S3 질의응답★  S4 카드  S5 평가  S6 계정  S7 문서  S8 관측
              |
[도메인]  수집 4  처리 6  색인 4  작업 2  검색 6  생성 7  관측 1  평가 5  카드 2  계정 5
              |
[포트]    SourceAdapter / LLMPort / EmbeddingPort / RerankerPort   (+ 추적 데코레이터)
              |
[기반]    Config / Logger / Database / Repositories 8종
```

**컴포넌트 60종 / 서비스 8종 / 포트 4종 / 유닛 5개**

### 2.2 이 설계가 지키려는 것

이 시스템의 요구사항 중 **양보할 수 없는 것은 근거 추적성**입니다 (SC-2, SC-3, NFR-5, NFR-6).
설계 전반이 그 하나를 향해 구성되어 있습니다.

| 요구 | 설계상의 장치 |
|---|---|
| 답변의 모든 문장에 출처가 있어야 한다 | C38이 **구조화 JSON**으로 `{문장, 근거 ID}`를 반환 → 문장과 근거가 자료구조로 결합 |
| 출처가 실제로 그 내용을 담아야 한다 | C40이 문장별 근거 지지를 검증, C46이 골든셋과 대조하여 수치화 |
| 근거가 없으면 답하지 않아야 한다 | C39(생성 전) + C40(생성 후) **2단 거부** |
| 인용을 클릭하면 원문을 볼 수 있어야 한다 | 원문 **3계층 보존**과 문자 오프셋 유지로 C41이 정확한 구간을 역참조 |
| 문서에 숨은 지시문이 시스템을 조작하면 안 된다 | C37이 문서 내용을 **데이터 영역으로 격리** |
| 품질이 나빠지면 즉시 알아야 한다 | C48이 기준선과 비교하여 회귀 시 CI 실패 |

## 3. 설계 결정 (DD-1 ~ DD-25)

### 3.1 설계 질문에서 확정된 결정 (DD-1~DD-18)

| ID | 결정 | 근거 | 파급 |
|---|---|---|---|
| **DD-1** | 기능(도메인) 모듈 상위 + 공용 기반 계층(`core`/`db`/`ports`/`adapters`) 병존 | DQ-1=B | 유닛 경계와 패키지 경계 일치. **⚠️ §5 확인 요망** |
| **DD-2** | 단일 `SourceAdapter` 프로토콜 + 소스별 구현 4종 | DQ-2=A | 오케스트레이터가 소스 종류를 몰라도 동작. 소스 추가가 구현체 추가로 끝남 |
| **DD-3** | 문서 처리를 **명시적 단계 객체 체인**으로 구성 | DQ-3=A | 단계 경계 = 재개 지점. 부분 실패 복구(FR-8)가 구조적으로 가능 |
| **DD-4** | 원문 **3계층 보존** (원본 파일/URL → 추출 텍스트+오프셋 → 청크) | DQ-4=A | FR-19 스니펫 하이라이트의 전제. 저장 용량 증가는 감수 |
| **DD-5** | 검색을 독립 컴포넌트로 분리하고 파이프라인이 조립 | DQ-5=B | 리랭커 on/off와 K 변경이 설정만으로 가능 → R-4 완화, u4 비교 실험 가능 |
| **DD-6** | AI 포트를 **3분할** (LLM / Embedding / Reranker) | DQ-6=B | 각각 독립 교체 가능. 임베딩 교체 시 재색인 필요 여부를 `model_id()`로 판정 |
| **DD-7** | 프롬프트를 **저장소 내 템플릿 파일 + 버전 식별자**로 관리 | DQ-7=A | 평가 결과에 프롬프트 버전이 기록되어 품질 변화 원인 추적 가능 |
| **DD-8** | 인용을 **LLM 구조화 출력(JSON)** 으로 획득 | DQ-8=A | **가장 파급이 큰 결정.** 검증(C40)과 매핑(C41)이 결정론적이 됨 |
| **DD-9** | 거부를 **2단**으로 판정 (검색 임계값 + 생성 후 검증) | DQ-9=B | FR-20과 FR-21이 각각 다른 실패 모드를 막음 |
| **DD-10** | 물질 카드는 **구조화 DB 직접 조회**, LLM 미사용 | DQ-10=A | NFR-3(1초)과 NFR-8(추정 금지)을 동시에 만족 |
| **DD-11** | 동의어를 **별도 테이블**로 정규화 색인 | DQ-11=A | CAS·UN·이명의 정확 일치 보장 |
| **DD-12** | **Thin router + Fat service** | DQ-12=A | 서비스가 HTTP를 모르므로 CLI·워커에서 동일 로직 재사용 |
| **DD-13** | 작업 상태를 **자체 `Job`/`JobItem` 테이블**로 관리 | DQ-13=A | 진행률·부분 실패·재개가 큐 백엔드와 무관해짐 → 큐 교체 가능 |
| **DD-14** | 컴포넌트 간 **직접 호출**, 비동기 경계에서만 큐 사용 | DQ-14=A | 단일 배포 단위에 이벤트 버스는 과설계 |
| **DD-15** | **SQLAlchemy 2.x ORM + Alembic**, pgvector 통합 | DQ-15=A | 벡터·관계형 데이터가 한 트랜잭션에 포함됨 (DD-23) |
| **DD-16** | LLM 추적을 **포트 데코레이터**로 구현 | DQ-16=A | 추적 누락이 구조적으로 불가능. 서비스에 관측 코드 없음 |
| **DD-17** | 인용 스니펫은 **서버 렌더 + 최소 JS 토글**, JS 없이도 링크로 열람 | DQ-17=A | 접근성 확보, 프론트 복잡도 최소화 |
| **DD-18** | 평가의 1차 진입점은 **CLI** | DQ-18=A | CI 회귀 테스트(NFR-26) 연동이 자연스러움 |

### 3.2 설계 과정에서 도출된 결정 (DD-19~DD-25)

| ID | 결정 | 근거 |
|---|---|---|
| **DD-19** | `Scope`(검색 범위)를 검색 계열 메서드의 **필수 인자**로 둔다 | 소유자 필터 누락이 호출 시점에 드러나야 함 (NFR-15). 기본값을 두면 누락이 조용히 통과 |
| **DD-20** | 도메인 컴포넌트는 **DB 세션을 받지 않고** 리포지터리를 통해서만 접근한다 | 검색·생성 로직을 인메모리 스텁으로 테스트 가능 (NFR-24, NFR-28) |
| **DD-21** | 후행 유닛의 확장 지점을 **선행 유닛 설계에 미리 반영**한다 — `Chunk.owner_id`(u5용), `scope` 인자(u5용), `substance_synonym` 테이블(u3용) | 방향 (a) 단계적 진행에서 후행 유닛이 스키마를 바꾸면 전체 재색인이 발생 |
| **DD-22** | 평가(S5)는 **`S3 QueryService`를 그대로 호출**한다 | 평가 경로와 실사용 경로가 다르면 평가 수치가 무의미해짐 |
| **DD-23** | 벡터 인덱스와 키워드 인덱스는 **동일 PostgreSQL 트랜잭션**에 포함한다 | 두 인덱스 간 불일치가 구조적으로 발생하지 않음 (DD-15의 이득) |
| **DD-24** | 수집·색인의 트랜잭션 경계는 **문서 1건 = 1 트랜잭션**이다 | 장시간 락 방지 및 부분 성공(FR-8) 보존 |
| **DD-25** | **1단 거부 시 LLM을 호출하지 않는다** | FR-20의 요구이자 비용·지연 절감. 거부 응답은 원문 링크만 포함 |

## 5. ⚠️ 승인 전 확인 요망

### DD-1 — 패키지 구성이 DQ-1의 B와 C 사이에 있습니다

DQ-1 답변은 **B(기능 기준)** 였습니다. 그러나 여러 도메인 모듈이 공유하는 설정·로깅·DB 세션·포트
정의는 특정 도메인에 귀속시킬 수 없어 `core/`, `db/`, `ports/`, `adapters/` **공용 기반 계층**을
두었습니다. 이는 실질적으로 DQ-1의 **C(혼합)** 에 가깝습니다.

- **그대로 진행** — 도메인 모듈 + 공용 기반 계층 (현재 설계)
- **순수 B로 변경** — 공용 요소를 각 도메인 모듈에 복제하거나 첫 사용 모듈에 귀속

**권장**: 그대로 진행. 공용 요소 복제는 설정·로깅의 일관성을 깨뜨립니다.
