## P7. 물질 검색 (FR-23, FR-26)

```
┌────────────────────────────────────────────────────────┐
│  물질 안전 카드                                          │
├────────────────────────────────────────────────────────┤
│  [ 황산  또는  7664-93-9              ] [ 검색 ]         │
│                                                        │
│  ℹ️ 검색 가능: 국문명 · 영문명 · CAS 번호                 │
│     UN 번호와 이명(異名)은 현재 데이터가 없습니다.         │  ← BR-109·110
├────────────────────────────────────────────────────────┤
│  검색 결과 3건 — 물질을 선택하십시오                      │  ← BR-101
│                                                        │
│  · 황산 (SULFURIC ACID)      CAS 7664-93-9   [국문명 일치] │
│  · 황산구리 (COPPER SULFATE) CAS 7758-98-7   [국문명 일치] │
│  · 발연황산 (OLEUM)          CAS 8014-95-7   [국문명 일치] │
└────────────────────────────────────────────────────────┘
```

| ID | 요소 | 동작 |
|---|---|---|
| **FE-24** | 검색 입력 | 단일 텍스트. 정규화는 서버가 한다 (BR-100) |
| **FE-25** | 지원 키 안내 | **UN·이명 미지원을 상시 표시** (BR-109·110) |
| **FE-26** | 후보 목록 | **1건이어도 목록을 거치지 않고 바로 카드로.** 2건 이상이면 반드시 선택 |
| **FE-27** | 일치 근거 배지 | `[국문명 일치]` `[CAS 일치]` — 왜 후보인지 (BR-101) |

### 시스템이 고르지 않는다

"황산"으로 검색해 "황산구리"가 함께 나오는 것은 정상이며, **둘 중 하나를 시스템이
골라 카드를 띄우지 않는다.** 사용자가 다른 물질의 카드를 보고 있다는 것을 알 방법이
없기 때문이다(R-6, BR-101).

### 0건

```
┌────────────────────────────────────────────────────────┐
│  ⓘ "다이옥신"에 해당하는 물질을 찾지 못했습니다.          │
│     현재 코퍼스에는 물질 40건이 등록되어 있습니다.        │
└────────────────────────────────────────────────────────┘
```
오류가 아니다. 검색어를 그대로 되비추어 오타를 사용자가 알아볼 수 있게 한다.

MSDS 가 있는 물질(약 7건)에서는 같은 자리에 본문과 출처가 채워지고, **출처가 여럿이면
전부 나열된다**(BR-103):

```
│  ④ 권장 개인보호구                                      │
│     • 분진·미스트 발생 시 방진마스크를 착용한다.          │
│       📄 황산 MSDS — 남해화학 · msds_08  🔗 원문         │
│     • 내산성 보호장갑과 보안경을 착용한다.                │
│       📄 황산 MSDS — 코리아케미칼 · msds_08  🔗 원문      │
```

| ID | 요소 | 비고 |
|---|---|---|
| **FE-28** | 물질 헤더 | 국문·영문·CAS. UN 은 값이 있을 때만 (현재 없음) |
| **FE-29** | 면책 문구 | **항상 표시, 접히지 않음** (FR-35) |
| **FE-30** | 결측 고지 | **`missing_count > 0` 일 때만.** 없으면 숨김 (BR-106) |
| **FE-31** | 항목 블록 ×7 | **항상 7개, 고정 순서.** 빈 항목도 자리를 지킨다 (BR-102) |
| **FE-32** | 항목 값 | 원문 그대로. 요약하지 않음 (BR-104) |
| **FE-33** | 값 출처 | 문서 제목 · 섹션 라벨 · 원문 링크 (BR-105) |
| **FE-34** | 노출경로 하위 항목 | 응급조치에만. 흡입·피부·눈·경구 (BR-103, FQ4-7) |

## 표시 원칙

1. **7항목은 언제나 7개다** (BR-102). 값이 없어도 빼지 않는다 — 빼면 카드가
   완전해 보이고, 사용자가 "정보가 없다"와 "화면이 안 보여준다"를 구분할 수 없다.
2. **"정보 없음"이라고 쓴다.** 빈칸으로 두지 않는다 — 빈칸은 로딩 실패처럼 읽힌다
   (u2 BR-90 과 같은 이유).
3. **결측 개수를 밝힌다** (BR-106). u2 의 "제거된 문장 N개"(BR-88), "단가 미등록
   N건"(BR-96)과 같은 장치다.
4. **출처가 여럿이면 전부 보인다** (BR-103). 값이 서로 달라도 하나로 고르지 않는다 —
   불일치 자체가 사용자가 알아야 할 사실이다.
5. **본문은 원문 그대로, 줄바꿈 보존.** 요약하지 않는다 (BR-104).
6. **면책 문구는 접히지 않는다** (FR-35).
7. **UN·이명 미지원을 검색 화면에 상시 표시한다** (BR-109·110). 조용히 0건을
   돌려주면 사용자는 자기 입력이 틀렸다고 생각한다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/substances?q=…` | 검색 — 후보 0..N |
| `GET` | `/api/substances/{id}` | 카드 (7항목 + 결측 정보) |

**SSE 가 아니라 평범한 JSON 이다**(FQ4-14). 스트리밍할 것이 없다 — 구조화 조회는
한 번에 끝나고, u2 실측에서 순수 DB 경로는 26ms 였다(NFR-3 예산 1초).

### `GET /api/substances?q=황산`
```json
{
  "query": "황산",
  "matches": [
    {"substance_id": 12, "cas_number": "7664-93-9",
     "name_ko": "황산", "name_en": "SULFURIC ACID", "matched_on": "name_ko"}
  ],
  "unsupported_keys": ["un", "alias"]
}
```
`unsupported_keys` 가 응답에 있는 이유: 화면이 그 사실을 **빠뜨릴 수 없게** 하기
위해서다(BR-109·110). u2 의 `unpriced_calls` 와 같은 장치다.

### `GET /api/substances/12`
```json
{
  "substance": {"substance_id": 12, "cas_number": "7664-93-9",
                "name_ko": "황산", "name_en": "SULFURIC ACID", "un_number": null},
  "has_msds": false,
  "missing_count": 6,
  "items": [
    {"key": "ghs", "label": "GHS 분류 및 신호어", "values": []},
    {"key": "first_aid", "label": "응급조치 요령", "values": [
      {"text": "기도·점막 자극성, 두통·현기증…", "route": "inhale",
       "document_id": 73, "document_title": null,
       "section_code": "substance_inhale", "section_title": "흡입",
       "source_url": "https://www.data.go.kr/…", "origin": "substance_api"}
    ]}
  ]
}
```

**`values: []` 는 오류가 아니다.** 40건 중 대부분이 그렇고, `missing_count` 가
그 사실을 함께 전달한다.

## u1·u2 와의 공유

| 항목 | 재사용 |
|---|---|
| 레이아웃·CSS | u1 `templates/base.html` |
| 네비게이션 | **`물질` 탭 추가** — 질의 / 사용량 / **물질** / 대시보드 / 소스 / 작업 |
| 섹션 라벨 표기 | u2 `citations.display_label` (BR-90) |
| 면책 문구 | u2 P5 와 동일 문구 (FR-35) |
| 정규화 | u1 `normalize()` (BR-100) |

**질의 화면(P5)에서 카드로 연결하지 않는다**(FQ4-13=A). 유용하지만 새 상호작용이며,
붙이지 않는 것이 u3 을 작게 유지한다. u2 의 질의 경로는 무상태이고(FR-22) 카드는
별개의 조회다.
