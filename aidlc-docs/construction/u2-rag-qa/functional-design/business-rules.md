# Business Rules — u2-rag-qa

**유닛**: `u2-rag-qa` (2/5)
**작성일**: 2026-08-24
**번호**: BR-63 ~ BR-96 (u1 은 BR-01~BR-62)

---

## 1. 질의 해석 (BR-63 ~ BR-66)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-63** | 질의문은 색인과 **동일한 정규화**(u1 C16)를 거친다. 다른 정규화를 쓰면 완전일치 검색이 어긋난다 | FR-14 |
| **BR-64** | CAS·UN 번호는 정규식으로 먼저 추출한다. 규칙으로 해석되면 **LLM 을 호출하지 않는다** | FR-17, NFR-1 |
| **BR-65** | 물질명은 `substance_synonym` 을 거쳐 표준명으로 해석한다. 해석되지 않으면 **원문 그대로** 키워드 검색에 넘긴다 | FR-17 |
| **BR-66** | 문서 유형 힌트는 **가중치이지 필터가 아니다.** 필터로 쓰면 질문이 조금만 어긋나도 정답 문서가 후보에서 사라진다 | FR-17, NFR-8 |

## 2. 검색 (BR-67 ~ BR-72)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-67** | 키워드·벡터 검색은 **각 30건**, 융합 후 **20건**, 최종 **5건** | FQ2-2 |
| **BR-68** | 융합은 **RRF**, `k=60`. 순위만 사용하므로 두 검색의 스코어 스케일을 정규화할 필요가 없다 | FQ2-1 |
| **BR-69** | 융합 결과가 한 문서 유형으로만 채워지면, 다른 유형에서 각 1건을 최하위와 교체한다. **해당 유형에 후보가 없으면 교체하지 않는다** | FQ2-3, 실측(법령 69%) |
| **BR-70** | 리랭커는 **기본 비활성**이며 별도 컨테이너에서 실행한다. `app` 은 메모리 한도 2 GiB 중 85% 를 이미 쓴다(실측) | FQ2-4, R-4 |
| **BR-71** | 리랭커 호출이 실패·타임아웃하면 **융합 순위를 그대로 사용**하고 경고를 남긴다. 검색 전체를 실패시키지 않는다 | R-4 |
| **BR-72** | 한쪽 검색이 실패해도 다른 쪽만으로 진행한다. **양쪽 모두 실패해야** 오류다 | NFR-23 |

## 3. 거부 (BR-73 ~ BR-78)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-73** | **1단 거부** — 최상위 근거 스코어가 임계값 미달이면 **LLM 을 호출하지 않고** 거부한다 | FR-20, FQ2-6 |
| **BR-74** | 임계값은 환경변수로 설정하며 운영 화면에서 조정 가능하다. 기본값은 u4 골든셋으로 캘리브레이션한다 | NFR-7, FQ2-7 |
| **BR-75** | 거부 응답에는 **반드시 원문 링크 목록을 포함**한다. "모른다"만 반환하면 사용자가 갈 곳이 없다 | FR-20, BR-32 |
| **BR-76** | **2단 거부** — 남은 문장이 0건이면 답변이 아니라 거부다 | FR-21, FQ2-10 |
| **BR-77** | LLM 이 `stop_reason = refusal` 을 반환하면 `provider_refusal` 로 거부한다. 이를 오류로 처리하면 재시도가 반복된다 | FR-20 |
| **BR-78** | 거부는 **실패가 아니다.** `query_log.outcome` 에 거부 사유를 기록하고 오류 지표에 넣지 않는다 | SC-3 |

## 4. 답변 생성 (BR-79 ~ BR-84)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-79** | 답변은 **구조화 출력으로 강제**한다. 스키마는 `{sentences: [{text, chunk_ids}]}` | FR-18·19, FQ2-11 |
| **BR-80** | **모든 문장은 최소 1개의 근거를 인용해야 한다.** 인용 없는 문장은 1회 재시도 후 제거한다 | FR-19, FQ2-12 |
| **BR-81** | LLM 이 반환한 `chunk_id` 가 **실제로 넘긴 근거 목록에 없으면** 그 인용을 제거한다. 존재하지 않는 청크를 인용하는 것이 가장 나쁜 실패다 | FR-19, R-6 |
| **BR-82** | 생성은 **검색된 근거만으로** 수행한다. 모델의 사전지식으로 보충하지 않는다 | FR-18, NFR-6 |
| **BR-83** | Anthropic **네이티브 citations 기능을 사용하지 않는다.** `output_config.format` 과 동시 사용이 불가(400)하고, BR-30 오프셋이 원문까지 이어지는 더 나은 출처를 이미 제공한다 | FQ2-11, BR-30 |
| **BR-84** | 답변에는 **항상 면책 문구를 부착**한다. 거부 응답에도 부착한다 | FR-35 |

## 5. 근거 지지 검증 (BR-85 ~ BR-88)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-85** | 각 문장은 **자신이 인용한 근거만으로** 지지 여부를 판정한다. 다른 근거로 지지되는 것은 지지가 아니다 | FR-21 |
| **BR-86** | 문장별 검증은 **병렬 호출**한다. 순차 호출은 문장 수만큼 지연이 누적된다 | NFR-1 |
| **BR-86a** | *(2026-08-25 명시)* 2단 검증은 **문장 수만큼 LLM 호출을 추가**한다. 질의 1건당 호출 수는 `1 + 문장 수`(+엔티티 추출 시 1)이며, 답변이 3~6문장이면 **호출이 4~7배**가 된다. 비용은 `verify` 프롬프트가 짧아 토큰 기준으로는 완화되지만 **호출 수는 그대로다**. `E18.purpose` 로 `answer` 와 `verify` 를 분리 집계하는 이유가 이것이며, P6 이 용도별 분해를 보여주는 것도 이 비용을 감출 수 없게 하기 위해서다 | FQ2-8, NFR-19, FR-42 |
| **BR-87** | 검증 호출이 실패하면 `unverified` 로 기록하고 **제거한다.** 검증하지 못한 것을 지지로 간주하지 않는다 | R-6, NFR-6 |
| **BR-88** | 문장이 제거되면 사용자에게 **제거 사실을 표시**한다. 조용히 지우면 답변이 완전해 보인다 | FQ2-9, NFR-8 |

## 6. 인용 표시 (BR-89 ~ BR-92a)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-89** | 스니펫은 `extracted_text.text[start_offset:end_offset]` 이다. **BR-30 이 이를 보장**하므로 별도 검색을 하지 않는다 (실데이터 1,564청크 위반 0건) | FQ2-17, BR-30 |
| **BR-90** | `section_code` 가 NULL 이면 **"섹션 정보 없음"** 을 명시한다. 청크 순번을 섹션처럼 표기하지 않는다 | FQ2-18, NFR-8, BR-20a, BR-31a |
| **BR-91** | 모든 인용에 **원문 링크**(`document.source_url`)를 붙인다 | BR-32 |
| **BR-92** | 답변 확정 직후 **인용 스냅샷을 동결**한다. 재색인(BR-54)이 청크를 교체해도 과거 답변의 근거가 남아야 한다. *(2026-08-25 보강)* 동결은 답변 확정과 **같은 트랜잭션**이며, 실패하면 답변 전체를 롤백하고 `error` 로 응답한다 | BR-54, FR-19 |
| **BR-92a** | *(2026-08-25 신설)* **인용 표시는 `citation_snapshot` 만 읽는다.** `chunk` 를 조인하지 않는다. `answer_citation.chunk_id` 는 SET NULL 이므로 재색인 후 NULL 이 될 수 있고, NULL 은 정보 소실이 아니라 "재색인되었다"는 사실이다. 표시에 필요한 것은 전부 스냅샷에 NOT NULL 로 있다 | BR-92, BR-54 |

## 7. 프롬프트 (BR-93 ~ BR-94)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-93** | 프롬프트는 `prompts/<name>/<semver>.md` 에 저장하고 `prompts/index.yaml` 로 활성 버전을 지정한다. 코드에 문자열로 두지 않는다 | NFR-22, FQ2-15 |
| **BR-94** | 프롬프트 캐시를 위해 **고정 내용을 앞, 질문을 맨 뒤**에 배치한다. 캐시는 접두사 일치라, 매 요청 바뀌는 질문이 앞에 오면 캐시가 전혀 동작하지 않는다 | NFR-1, NFR-20 |

## 8. 추적 (BR-95 ~ BR-96)

| # | 규칙 | 근거 |
|---|---|---|
| **BR-95** | 모든 LLM 호출에 `model`, `purpose`, `prompt_name`, `prompt_version`, 토큰 수, 지연을 기록한다. 실패한 호출도 기록한다 | FR-41, FQ2-16 |
| **BR-96** | 단가가 등록되지 않은 모델의 비용은 **NULL** 이다. 0 으로 기록하면 사용량 화면이 "무료"라고 거짓말한다. 화면은 합계에서 제외하되 **제외 건수를 함께 표시**한다 | NFR-8, NFR-19, FQ2-19 |

## u1 규칙과의 관계

| u1 규칙 | u2 에서의 의미 |
|---|---|
| **BR-30** 오프셋 무결성 | BR-89 의 **전제**. 이것이 깨지면 스니펫이 엉뚱한 본문을 보여준다 |
| **BR-32** source_url 필수 | BR-75, BR-91 의 전제 |
| **BR-20a** 뒤섞인 PDF 강등 | BR-90 이 처리해야 하는 대상. 잘못된 섹션 라벨로 인용하는 것보다 라벨 없이 인용하는 것이 낫다 |
| **BR-31a** 소형 레코드 통합 | 사고사례의 인용 단위는 "사고 1건". BR-90 이 처리 |
| **BR-54** 재색인 전량 교체 | BR-92 와 **충돌**했다. *(2026-08-25 해소)* 동결을 **답변 트랜잭션**으로 옮기고 `chunk_id` 를 **SET NULL** 로 두어, u1 재색인 경로는 **변경 없이** 그대로 동작한다. 표시는 BR-92a 에 따라 스냅샷만 읽는다 |
| **BR-44** 원본 보존 | 재색인의 존재 이유. BR-20a·BR-31a·BR-27a 가 전부 이 경로로 배포되었다. **u2 가 이 능력을 막아서는 안 된다** — BR-92a 가 그 보증이다 |
| **BR-02** 키 미설정 시 소스만 실패 | `ANTHROPIC_API_KEY` 미설정 시 질의 기능만 비활성, 앱은 기동 |
