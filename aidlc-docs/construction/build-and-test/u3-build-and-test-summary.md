## 5. ⚠️ 발견 — 짧은 문서는 카드에 닿지 않는다 (BR-31a ↔ BR-104)

7/7 결측 2건의 원인이 서로 다르고, 하나는 **데이터가 있는데 못 쓴다**.

| 물질 | 원인 |
|---|---|
| 메틸 에틸 케톤 (78-93-3) | 출처 레코드 자체가 식별자뿐. 응급조치 4경로가 전부 비어 있다. **정직한 결측** |
| 4-tert-뷰틸벤조산 (98-73-7) | **섹션 7개에 내용이 있는데 카드가 못 읽는다** |

```
문서 69  structured  섹션 7개(inhale·skin·eyeball·oral 전부 내용 있음)  청크 1개  section_id NULL
문서 86  structured  섹션 7개                                        청크 7개  섹션별 1개
```

원인은 **BR-31a** 다. 문서의 섹션 중앙값이 `MIN_CHUNK_TOKENS`(20) 미만이면 문서 전체를
섹션 없는 청크 하나로 접는다 — 인용 단위가 못 되는 조각을 만들지 않기 위해서다.
그런데 카드는 `section_code` 로만 항목을 찾으므로(BR-104), 접히는 순간 **그 문서의
내용 전부가 카드에서 사라진다.**

전 코퍼스 영향 범위:
```
섹션 2개 이상 + 섹션 있는 청크 0개 인 문서 = 13건
  incident_data   12건  ← 카드가 읽지 않는 문서 타입. 영향 없음
  ncis_substance   1건  ← 문서 69. 카드 1건이 통째로 빈다
```
**카드 49건 중 1건.** 규칙은 설계대로 동작하고 있고, 두 규칙이 짧은 문서에서 만나면
이런 결과가 나온다는 사실이 지금까지 드러나지 않았을 뿐이다.

선택지 (u3 범위 밖 — 청킹 규칙 변경은 전 코퍼스 재색인 35분을 동반한다):
- **A** BR-31a 를 "섹션이 있으면 접지 않는다"로 좁힌다 — 짧은 청크가 늘어난다
- **B** 접은 청크에 원 섹션 목록을 메타로 남긴다 — 카드가 그것으로 항목을 찾는다
- **C** 현상 유지 + 기록 — 영향 1/49

**결함으로 올리지 않았다.** 코드가 규칙을 어긴 것이 아니라 두 규칙의 경계가 만난
것이고, 어느 쪽으로 갈지는 설계 결정이다.
