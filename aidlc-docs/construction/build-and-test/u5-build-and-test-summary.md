## 2. 격리 — 세 겹이 각각 다른 것을 잡았다

### ① 통합 (실 DB, 11건)
두 계정과 각자의 문서를 만들고, 검색 경로별로 확인한다.
```
alice 스코프로 bob 의 청크 검색   → 0건
bob  스코프로 bob 의 청크 검색    → 있음        (전부 숨기는 필터는 무의미하다)
공개 스코프로 둘 다 검색          → 0건
공개 코퍼스는 익명·로그인 모두에게 → 보인다 (BR-147)
남의 문서 / 공개 문서 / 없는 문서  → 전부 같은 오류 (BR-146)
```

### ② 정적 (4건) — **실제로 일을 했다**
`Scope(` 를 C55 밖에서 만드는 코드를 금지한다. 이 검사가
`web/routers/query.py` 의 하드코딩된 공개 스코프를 찾아냈다.

**통합 테스트만 있었다면 통과했을 것이다** — 그 경로를 덮는 테스트가 아직
없었기 때문이다. 스트리밍 질의만 남의 것도 내 것도 아닌 공개 스코프로 돌아,
같은 질문에 SSR 은 내 업로드를 찾고 스트리밍은 못 찾는 상태가 됐을 것이다.

### ③ HTTP 종단 (5건)
```
B 목록에 A 파일명            없음
B 가 A 문서 삭제 시도        404
B 가 A 문서 재색인 시도       404
B 가 A 원본 다운로드          404
A 가 자기 원본 다운로드       200 · application/pdf
```

## 3. 보안 실측

### 인증
| 항목 | 결과 |
|---|---|
| CSRF 토큰 없음 / 불일치 | **400** (BR-138) |
| 세션 쿠키 | `HttpOnly=True` · `SameSite=lax` · `Secure=false`(로컬 HTTP) |
| 오픈 리다이렉트 `?next=//evil.example.com` | `/` 로 무력화 |
| 로그인 실패 응답 시간 | 존재 계정 **97.5ms** / 없는 계정 **89.0ms** |
| `JWT_SECRET` 없이 기동 | **RuntimeError** — 규칙 근거를 담은 메시지 |

**응답 시간 차이 8.5ms(약 9%)** 는 argon2 비용이 지배하기 때문이다. 없는 계정에도
더미 해시를 검증하는 AP-1 이 실제로 동작한다 — 이 코드가 없으면 없는 계정은
1ms 안에 돌아왔을 것이다. **완전히 같지는 않다**는 사실을 그대로 적는다.

### 지수 백오프 (AP-2) — 설계대로 동작한다
```
시도 1~6:   68~108 ms
시도 7:   1,079 ms   ← 백오프 시작
시도 8:   2,091 ms   ← 2배
정상 비밀번호 → 즉시 로그인 성공 (잠금 없음)
```
**잠금이 아니라 지연**이라는 것이 실측으로 보인다. 공격자가 남의 계정을 잠글 수
없고, 정당한 사용자는 올바른 비밀번호로 즉시 복구한다.

### 업로드 거부 — 이유가 사용자에게 그대로 간다
```
확장자 위장   400  PDF 파일이 아닙니다 (파일 시작 바이트 불일치).
손상 PDF     400  PDF 를 읽을 수 없습니다: Stream has ended unexpectedly
자동 실행     400  자동 실행 요소가 포함되어 있습니다: /OpenAction
빈 파일      400  빈 파일입니다.
문서 수 한도  거부  문서 수 한도에 도달했습니다 (1건). 기존 문서를 삭제한 뒤…
용량 한도    거부  저장 용량 한도를 초과합니다.
```

### 이스케이프
```
로그인·가입 폼   <script> · "><img onerror> · '; DROP TABLE user_account; --
                 → 원문 반사 0, DB 무사
업로드 파일명     <img src=x onerror=alert(1)>.pdf
                 → 목록 화면에서 &lt;img 로 이스케이프
```

### 로그 (OP-1·OP-2) — 실제 파일을 훑었다
```
/logs/safeenv.log 최근 400KB
  세션 쿠키 값   0건      argon2 해시   0건
  이메일 전체    0건      JWT 형태 값   0건
  isolation_denied 3건 · login_failed 19 · login_succeeded 1
  upload_rejected 4 · upload_accepted 5
```
**마스킹이 지운 것이 아니라 애초에 들어가지 않는다** — 로그는 `user_id` 를 남기고
이메일을 남기지 않는다. 마스킹 확장(쿠키·이메일·argon2)은 실수로 흘러들어갔을 때의
2차 방어로 남는다.

`isolation_denied` 3건이 기록됐다는 것이 중요하다. **격리가 막은 순간을 볼 수 없으면
격리가 도는지 사후에 알 방법이 없다.**

```

  Recall@5    0.700 → 0.700   +0.000
  MRR         0.546 → 0.546   +0.000
  거부 정확도   0.400 → 0.400   +0.000
```

"u5 는 검색 경로를 건드리지 않는다"는 주장을 **숫자로 확인**했다. `incomparable`

## 5. Build & Test 에서 발견·수정한 결함 2건

### 결함 56 — 업로드 원본 링크가 한 번도 열린 적이 없다
목록 화면의 "원본" 링크가 `/documents/{문서 id}/file` 을 가리키는데, 라우트는
**UUID** 로 문서를 찾는다. `external_id == "151"` 은 아무것도 매칭하지 않으므로
**소유자에게도 404** 였다.

같은 실수가 `source_url` 에도 있었다: `/documents/{uuid}` 는 존재하지 않는 경로다
(`/file` 접미사가 빠졌다). 업로드 문서를 인용한 답변의 출처 링크가 전부 죽은 링크가
된다 — BR-105("모든 값에 확인 가능한 출처")를 정면으로 어긴다.

**링크를 따라가 보고 나서야 발견했다.** 화면은 정상으로 보였다.
→ `source_url = /documents/{uuid}/file`, 목록 링크는 `doc.uuid`.
수정 후: 소유자 200 · `application/pdf` · 431바이트, 타인 404.

### 결함 57 — (Code Generation 단계에서 이미 수정) 색인 실패가 보이지 않았다
빈 PDF 로 확인해 `job`+`job_item` 을 붙였다. Build & Test 에서 재확인:
```
⛔ 색인 실패   PDF produced no usable text (likely scanned image)
```

## 8. Ready for Operations — 조건부

### 충족

  실행(통합)·구조(정적)·종단(HTTP)

- **거부에는 언제나 이유가 붙는다** — 업로드·색인 실패 모두
- **`docker compose up` 단일 명령**으로 전체가 뜨고, 볼륨이 재기동을 넘긴다
