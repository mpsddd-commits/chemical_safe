## 4. 실측 — `evaluate --full` (실행 10, 21/30 채점)

```
골든셋 30문항 / 채점 21 / 미채점 9 / 할당량중단 1
Recall@5   0.591    MRR  0.380
정답률       0.762    인용 정확도  0.489    충실도  1.000
오거부율      0.045    거부 정확도   --
```

> Recall 이 3절과 다른 이유: 채점된 21문항에 **거부형이 하나도 없다**(골든셋 끝에
> 몰려 있다). 거부형은 Recall 1.0 으로 들어가므로 부분 실행의 평균은 더 낮게 나온다.
> **부분 실행의 지표를 전체 실행과 비교하면 안 된다** — `partial` 을 기준선으로
> 승격하지 않는 이유이기도 하다.

### 충실도 1.000 — 이 시스템은 지어내지 않는다

**정답이 틀린 5문항이 전부 `faithful: true` 였다.** 근거에 충실하게 답했는데
엉뚱한 근거를 받은 것이다. 심판의 말이 그대로 그렇게 적혀 있다:

```
law-07  "제공된 근거 본문의 내용(공단에 제출)을 충실히 반영하고 있어 충실성은 참이지만,
         기대 답변의 핵심 기관명(고용노동부장관)과 다른 기관(공단)을 제시했으므로
         정확성은 거짓입니다."
sub-06  "제공된 근거에 '암모니아'라는 명시적인 물질 정보가 없어 정보를 찾을 수 없다고
         정확히 답변하여 faithful 은 참이나, 기대 답변의 요지를 포함하지 못했습니다."
```

**NFR-6(충실도 위반 ≤5%)은 측정된 범위에서 충족한다 — 위반 0%.**
그리고 이 실행이 말하는 것은 하나다: **실패 원인은 생성이 아니라 검색이다.**

### 인용 정확도 0.489 — NFR-5(≥95%)에 크게 미달

두 가지를 같이 읽어야 한다.

1. **BR-125 근사는 과대평가 방향이다.** 정답 근거 섹션을 인용했어도 그 문장이 다른
   내용을 말할 수 있다. 즉 **참값은 0.489 이하**다.
2. **동시에 이 지표는 엄격하다.** 골든셋이 지정한 섹션이 아닌 다른 유효한 섹션을
   인용하면 오답으로 센다. Recall 0 인 문항(9건)은 인용 정확도도 0이 될 수밖에 없다.

**결론: 인용 정확도는 지금 검색 성능에 종속돼 있다.** 검색이 맞는 섹션을 못 주면
인용도 맞을 수 없다. NFR-5 를 올리는 길은 인용 로직이 아니라 검색이다.

### 심판(C47)은 실제로 동작한다

미검증이던 경로가 전부 돌았다. 두 판정이 **독립적으로** 갈리는 것도 확인됐다 —
19건 중 5건이 `correct=false, faithful=true`. 한 번의 호출로 둘을 받는 BR-126 이
값을 한 지점이다.

## 5. 할당량 → `partial` → 재개 → 종료코드 4

설계한 대로 돌았다.

```
1) evaluate --full        20문항 채점 → 심판 429 → msds-03 = quota_exhausted
                          run.status = partial
                          "할당량으로 중단되었습니다. 이어서: evaluate --resume 10"
2) evaluate --resume 10   msds-03 부터 재개, 1문항 더 채점 → 다시 429
                          exit=4
```

**종료코드 4가 1이 아닌 것이 핵심이다.** 할당량 소진은 품질 문제가 아니고, 4를
실패로 취급하면 무료 티어에서 CI 가 항상 빨간불이 된다.

### 종료코드 실측
```
--list                     0
없는 골든셋                 2
코퍼스에 없는 정답 근거      2   (실패한 참조를 전부 나열하고 종료)
모드 미지정                 3
partial                    4
```

있었다.** 실행해 보지 않았으면 셋 다 몰랐을 것이다.

결함 53 은 결함 48(통합 테스트가 실코퍼스 청크를 지웠다)과 같은 모양이다 —
**테스트가 자기가 검증하는 상태를 조용히 바꾼다.** 이번에는 데이터가 아니라
기준선이었다. 승격은 이제 컨텍스트 매니저가 원복하고, 테스트가 만든 실행에는
`note='integration-test'` 가 붙는다.

## 9. Ready for Operations — 조건부

### 충족
- **품질이 숫자가 됐다.** 검색·답변·거부·충실도가 문항 단위로 기록되고 비교된다
- **매일 돌릴 수 있는 회귀 방어가 있다** — `--retrieval-only`, LLM 0 호출, 수초
- **며칠에 걸친 실행이 끝까지 갈 수 있다** — 문항 단위 트랜잭션·재개·종료코드 분리
- **비교할 수 없는 것을 비교하지 않는다** — 코퍼스·모델·프롬프트가 다르면 `incomparable`
- **지표가 움직인 이유를 추적할 수 있다** — 실행마다 무엇을 측정했는지 통째로 기록

### 제약
| 항목 | 내용 |
|---|---|
| **심판 20/일** | 전체 1회 = 2일. 문서의 "7일"은 정정됐다 |
| **부분 실행 지표** | 문항 구성이 편향된다(거부형이 뒤에 몰려 있다). 기준선 승격 금지 |
| **인용 정확도 0.489** | 검색이 개선되기 전에는 이 숫자가 인용 로직을 말해주지 않는다 |
| **기준선 미승격** | 회귀 판정이 아직 동작하지 않는다. 첫 완주 실행이 첫 기준선 후보 |
