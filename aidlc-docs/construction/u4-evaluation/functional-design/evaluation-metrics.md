# Evaluation Metrics — u4-evaluation

지표 하나하나의 **계산식·입력·비용·한계**를 적는다. 한계를 적는 이유는 이 숫자들이
나중에 "품질이 이만큼이다"라고 인용될 것이기 때문이다 — 근사가 어디에 들어갔는지
모르면 그 인용이 거짓말이 된다.

---

## 0. 지표별 비용

| 지표 | LLM 호출 | 30문항 전체 실행 비용 |
|---|---|---|
| Recall@5 · Recall@10 | 0 | 0 |
| MRR | 0 | 0 |
| 거부 정확도 · 오거부율 | 0 | 0 |
| 인용 정확도 | 0 (답변이 이미 있으면) | 0 |
| 정답률 | 문항당 1 (심판) | 25 |
| 충실도 | 정답률과 **같은 호출** | 0 (추가분) |
| — 답변 생성 자체 | 문항당 5.25 | **131** |

**131 대 25.** 비용의 84%가 지표가 아니라 **답변을 만드는 데** 든다. 그래서
`--retrieval-only` 가 별도 모드로 존재한다.

## 1. Recall@k (FR-37)

```
정답근거 집합 G = 골든셋 문항의 evidence
검색결과 R_k  = 상위 k개 후보를 (문서, 섹션) 로 사영한 집합

Recall@k = |G ∩ R_k| / |G|
```

**적중 판정** (BR-113)
```
evidence.section 이 있으면   (document, section) 이 일치
evidence.section 이 없으면   document 만 일치
```

k = 5, 10 (BR-124).

**한계**: 초안 30문항의 `evidence` 는 대부분 1건이므로 Recall 이 0 또는 1 로만
나온다. 문항 수가 적을 때 이 지표는 **비율이 아니라 적중 개수**에 가깝다.
리포트에 `hit 22/25` 를 함께 낸다.

---

## 2. MRR (FR-37)

```
RR = 1 / (정답 근거가 처음 등장한 순위)     없으면 0
MRR = mean(RR)
```

Recall 과 달리 **순위**를 본다. 둘을 같이 보는 이유:
Recall@10 은 높은데 MRR 이 낮으면 "찾긴 하는데 뒤에 있다" — 융합(BR-68) 또는
리랭커(BR-70) 문제이고, 리랭커를 예산 안에서 못 쓴다는 u2 결론을 다시 볼 때
필요한 숫자다.

---

## 3. 정답률 (FR-37)

```
정답률 = (심판이 correct=true 로 본 문항 수) / (답변 기대 문항 수)
```

심판에게 주는 것:
```
질문 · 기대 답변 요지(answer_points) · 실제 답변 · 답변이 인용한 근거 본문
```
주지 **않는** 것: 골든셋의 정답 근거 위치. 주면 심판이 정답을 베낀다.

**왜 키워드 매칭이 아닌가**: 한국어에서 "보호장갑"과 "보호 장갑"이 다르고,
`simple` 설정에 형태소 분석이 없다 — 결함 25 에서 이미 같은 벽에 부딪혔다
(`plainto_tsquery` 가 "보호구는"으로 "보호구"를 못 찾았다).

**한계**: 심판도 모델이다. `judge_reason` 을 반드시 저장하는 이유가 이것이고
(BR-126), 지표가 크게 움직였을 때 사람이 읽을 대상이 된다.

---

## 4. 인용 정확도 (FR-37, NFR-5)

```
문장 s 의 인용 청크 c 가 정답 근거 소속이면 정확
인용 정확도 = (정확한 인용 수) / (전체 인용 수)
```

**이것은 근사다** (BR-125). NFR-5 의 문장은 "출처가 실제로 그 내용을 담고 있어야 함"
이고, 문자 그대로 하려면 문장마다 심판을 불러야 한다 — 문항당 5~9 호출이 더 붙어
무료 티어에서 실행이 불가능해진다.

근사의 방향은 **보수적이지 않다**: 정답 근거 섹션을 인용했는데 그 문장이 실제로는
다른 내용을 말할 수 있다. 즉 이 지표는 **과대평가될 수 있다.** 리포트에 그렇게 적는다.

> 대신 충실도(5절)가 다른 각도에서 같은 것을 본다. 두 지표가 갈리면 그 문항을
> 사람이 본다.

---

## 5. 충실도 faithfulness (FR-38, NFR-6)

```
충실도 = (심판이 faithful=true 로 본 문항 수) / (답변 기대 문항 수)
위반율 = 1 - 충실도            NFR-6 목표 ≤ 5%
```

심판 질문: **"이 답변의 모든 주장이 주어진 근거 본문으로 뒷받침되는가?"**

u2 의 문장별 검증(BR-86a, `verify`)과 **다른 것을 본다**:
- `verify` 는 문장 하나가 그 문장이 인용한 청크로 뒷받침되는지 — 파이프라인 내부
- 충실도는 답변 전체가 근거 전체와 모순되지 않는지 — 파이프라인 밖에서 다시

같은 것을 두 번 재는 게 아니라, **검증을 통과한 답변 중에 여전히 틀린 것이 있는지**
를 재는 것이다. 결함 37(검증 타임아웃이 모든 답변을 비움)은 전자가 무너져도
후자가 있으면 잡혔을 종류다.

## 6. 거부 정확도 · 오거부율 (FR-37, SC-3)

```
거부 정확도 = (expects=refusal 이고 outcome 이 refused_* 인 수) / (expects=refusal 수)
오거부율   = (expects=answer  이고 outcome 이 refused_* 인 수) / (expects=answer 수)
```

**두 숫자는 항상 같이 나간다** (BR-128). 거부 정확도만 보면 **전부 거부하는 시스템이
만점**을 받는다.

초안 골든셋의 거부 5문항 중 2건이 이 지표의 실제 값을 결정한다:

| 문항 | 난이도 |
|---|---|
| ref-01 날씨 · ref-02 파이썬 · ref-03 의료 | 쉽다. 코퍼스와 완전히 무관 |
| **ref-04 카드뮴** | 도메인 안. 법령 조문이 유사도상 걸릴 수 있다 |
| **ref-05 벤젠** | 도메인 안 + 마스터에 "1-클로로-2,4-다이나이트로벤젠"이 있다 |

ref-05 는 결함 45(완전일치가 코사인을 뒤집음)와 같은 부류의 회귀를 노린다.

## 7. 집계와 회귀 판정

### 기준선 대비 변화표 (C48)

```
지표                  기준선(run 3)   이번(run 7)    변화
Recall@5                    0.84          0.80      -0.04  ⚠
Recall@10                   0.92          0.92       0.00
MRR                         0.71          0.66      -0.05  ⚠ 회귀
정답률                       0.80          0.84      +0.04
인용 정확도                   0.91          0.91       0.00
거부 정확도                   1.00          1.00       0.00
오거부율                      0.04          0.04       0.00
충실도                       0.96          0.96       0.00
```

### 회귀 임계 (BR-130)

| 지표 | 허용 하락 폭 |
|---|---|
| Recall@5 · Recall@10 · MRR | 0.05 |
| 정답률 · 충실도 | 0.05 |
| 인용 정확도 | 0.03 |
| 거부 정확도 | 0.00 — **한 건도 놓치면 회귀** |
| 오거부율 | +0.05 (상승이 나쁨) |

거부 정확도만 0인 이유: SC-3(근거 없으면 답하지 않는다)은 안전 도메인의 핵심
약속이고, 30문항에 5건뿐이라 한 건이 0.20 이다.

**임계값은 초안이다.** 첫 기준선이 생기기 전까지는 실측이 없고, 실측 없는 임계값은
결함 34(예산에서 타임아웃을 유도했다가 성공한 호출을 죽임)와 같은 종류의 실수다.
첫 `--full` 실행 후 재검토한다.

### 비교 불가 (`incomparable`)

다음이 다르면 델타를 계산하되 **경고를 붙이고 회귀 판정을 하지 않는다**:
`corpus_fingerprint` · `answer_model` · `judge_model` · `prompt_versions` · `config`

> 코퍼스가 78문서에서 90문서가 된 뒤의 Recall 하락은 회귀가 아니라 **다른 것을 잰 것**
> 이다. 이 프로젝트에서 코퍼스는 이미 네 번 바뀌었다.

## 8. 첫 실행에서 기대하는 것

숫자를 예측하지 않는다 — 예측한 숫자는 나중에 실측과 섞인다. 다만 **무엇을 볼지**는
정해 둔다.

| 관심 | 왜 |
|---|---|
| 법령 10문항의 Recall | 법령이 1,173청크로 코퍼스의 72%다. 여기가 낮으면 전체가 낮다 |
| CAS 문항(sub-01·04·07)의 MRR | BR-38 완전일치가 실제로 1위를 만드는가 |
| MSDS 4문항 | 문서 20·24 가 구조화에 실패했다. 그 영향이 검색에도 나타나는가 |
| ref-04 · ref-05 | 도메인 안 근거 없는 질문을 거부하는가 |
| 인용 정확도 vs 충실도의 차 | 4절의 과대평가가 실제로 일어나는가 |
