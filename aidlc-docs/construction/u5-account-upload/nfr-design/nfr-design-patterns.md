# NFR Design Patterns — u5-account-upload

**대상 NFR**: NFR-11(해싱) · NFR-12(JWT) · NFR-13(업로드 저장) · NFR-15(접근 통제)
+ NFR-14(비밀값 로깅) · NFR-30(비루트) · NFR-31(볼륨)
**Security Baseline**: 활성 (Q27=A) — u2 의 NFR-16 에 이어 두 번째

패턴마다 **무엇을 막는지**와 **막지 못하는 것**을 함께 적었다. 두 번째를 적지 않은
보안 문서는 실제보다 강해 보인다.

---

## 1. 신뢰 경계

u2 는 **코퍼스 텍스트**가 비신뢰였다. u5 는 경계가 하나 더 생긴다.

| 입력 | 신뢰 | 통제 |
|---|---|---|
| 이메일·비밀번호 | ❌ | 형식 검증 · 정규화 · argon2 · 실패 응답 동일화 |
| 쿠키의 JWT | ❌ | 서명 검증 · 만료 · 실패는 전부 `None` |
| **업로드 PDF 바이트** | ❌ | 매직 바이트 → 파서 → 페이지 수 → 위험 요소 (AP-3) |
| **업로드 PDF 의 텍스트** | ❌ | **u2 의 인젝션 방어가 그대로 적용된다** (SP-3·SP-4) |
| 문서 id 경로 파라미터 | ❌ | 소유권 확인 후 404 (AP-6) |
| CSRF 토큰 | ❌ | 서버 측 검증 (AP-2) |

### 새로 생긴 위협 중 가장 큰 것
**업로드 텍스트가 답변에 인용된다.** 사용자가 올린 PDF 안의 문장이 그대로 프롬프트에
들어가고, 그것은 u2 가 코퍼스에 대해 세운 위협 모델의 **사용자 통제 버전**이다.

다만 새 방어가 필요하지 않다 — SP-3(이스케이프 + 요청별 nonce)·SP-4(색인 시점 스캔)·
SP-5(탐지해도 제외하지 않는다)가 **색인 경로에 붙어 있고**, 업로드는 같은 색인 경로를
쓴다(BR-142). **이것이 "같은 경로로 색인한다"가 보안 결정이기도 한 이유다.**

그리고 격리가 폭발 반경을 제한한다: 업로드 텍스트는 **올린 사람의 질의에만** 들어간다.

## 2. 인증 패턴 (AP-1 ~ AP-4)

### AP-1. 실패를 구분하지 않는 로그인 (BR-134, FQ7-1)

```
계정 조회 → 없으면 더미 해시로 verify 를 그대로 수행
        → 결과와 무관하게 같은 메시지, 같은 경로
```

**막는 것**: 가입 여부 확인. 메시지로도, 응답 시간으로도.
**막지 못하는 것**: 가입 폼의 이메일 중복 검사는 여전히 존재 여부를 알려 준다 —
가입 자체가 그 정보를 필요로 하기 때문이다. 로그인 쪽만 닫는다.

### AP-2. 지수 백오프 (FQ7-1=a)

```
연속 실패 5회부터   1s → 2s → 4s → 8s → 16s → 30s (상한)
성공하면 카운터 0
잠금은 없다
```

`user_account.failed_attempts` · `last_failed_at` 두 컬럼이면 된다.

**막는 것**: 자동화된 시도의 처리량. argon2 자체의 비용과 곱해진다.
**막지 못하는 것**: **무차별 대입을 막지 않는다. 늦출 뿐이다.** 분산 시도나
낮은 빈도의 장기 시도에는 거의 무력하다. 실질 방어는 BR-133 의 비밀번호 정책이다.
**계정 잠금을 쓰지 않은 이유**: 공격자가 이메일만 알면 남의 계정을 잠글 수 있다 —
방어가 서비스 거부 도구가 된다.

### AP-3. 무상태 토큰 (BR-135·BR-136, FQ7-3=a)

```
HttpOnly · SameSite=Lax · Secure(운영) · Path=/
HS256 · exp 12시간 · JWT_SECRET 없으면 기동 실패
로그아웃 = 쿠키 삭제
```

**막는 것**: XSS 로 인한 토큰 탈취(JS 가 읽지 못한다). 서버 상태 없는 확장.
**막지 못하는 것**: **탈취된 토큰은 최대 12시간 유효하다.** 서버 측 무효화가
없으므로 로그아웃해도 이미 복사된 토큰은 살아 있다. 블랙리스트를 두지 않은 이유는
모든 요청이 상태 조회를 하게 되어 무상태의 이점이 사라지기 때문이고, **이 절충을
"무효화 지원"이라고 쓰지 않는다.**

### AP-4. CSRF 토큰 (BR-138)

상태를 바꾸는 폼 전부 — 가입·로그인·업로드·삭제·재색인.
세션 쿠키와 무관한 별도 토큰을 폼에 심고 서버가 대조한다.

**막는 것**: SameSite 를 지원하지 않거나 우회 가능한 경로에서의 교차 사이트 요청.
**왜 SameSite 만으로 부족한가**: 브라우저에 의존하는 방어이고, 되돌릴 수 없는
동작(삭제)에 브라우저 동작만 믿는 것은 얇다.

## 3. 업로드 패턴 (UP-1 ~ UP-4)

### UP-1. 선언이 아니라 내용을 본다 (BR-140)

```
1. 크기 ≤ 20MB           바이트만 — 가장 싸다
2. 매직 바이트 %PDF-      확장자·MIME 은 업로더의 주장
3. pypdf 파싱 성공
4. 페이지 수 ≤ 200
5. /JavaScript · /EmbeddedFile · /Launch · /OpenAction 없음
```

**순서가 규칙이다** — 싼 검사를 먼저 두어 20MB 초과 파일에 파서를 태우지 않는다.

**막는 것**: 확장자만 바꾼 파일, 파서를 통과하지 못하는 손상·위장 파일, 자동 실행
요소와 임베디드 파일.

**막지 못하는 것 — 이것을 "악성 파일 차단"이라고 쓰지 않는다**:
- 알려진 악성 코드 시그니처를 탐지하지 않는다 (안티바이러스가 아니다)
- 새로운 `pypdf` 취약점을 막지 못한다 — **파싱 자체가 공격면**이다
- 스테가노그래피·정상 PDF 안의 악의적 텍스트는 대상이 아니다

**가장 큰 방어는 규칙이 아니라 구조다**: 이 시스템은 업로드 파일을 **실행하지 않고
텍스트만 추출한다.** 렌더링도, 미리보기도, 링크 추적도, 외부 리소스 로딩도 없다.
안티바이러스를 넣지 않은 이유는 컨테이너와 정의 파일 갱신이 NFR-29(단일 명령 기동)와
충돌하고, 위 구조가 실효 방어의 대부분을 이미 차지하기 때문이다.

### UP-2. 검증 전에 저장하지 않는다 (W21)

거부된 파일은 디스크에 남지 않는다. 남으면 그 자체가 저장소가 된다.

### UP-3. 웹 루트 밖 · 생성된 이름 (NFR-13, BR-141, FQ7-4=a)

```
명명 볼륨 safeenv_uploads → /data/uploads/{owner_id}/{uuid}.pdf
appuser 소유 · 0700 · app 쓰기 · worker 읽기
원본 파일명은 document.upload_filename 컬럼에만
```

**막는 것**: 경로 순회(`../../etc/passwd`), 덮어쓰기, 정적 서빙을 통한 직접 접근.
**소유자 디렉터리를 두는 이유**: 격리 버그가 났을 때 **파일 시스템 수준에서 눈에
보인다.** `ls /data/uploads` 가 곧 감사다.
**`/data/originals` 와 분리하는 이유**: 수집 원본(BR-44)과 사용자 파일은 백업·삭제·
권한 정책이 다르다.

### UP-4. 사용자별 용량 한도 (FQ7-5=a)

```
사용자당  총 200MB · 문서 50건
초과 시 업로드 거부 + 이유 표시
```

**막는 것**: 한 사용자가 디스크를 채워 **다른 사용자의 업로드·색인을 함께 멈추는 것**.
**전역 감시만 두지 않은 이유**: 이미 찬 뒤에 알게 되고 **누가 채웠는지 모른다.**

## 4. 격리 패턴 (IP-1 ~ IP-3) ⭐

이 유닛의 중심이다. 격리는 **조용히 깨지고, 깨진 것을 아무도 모른다.**

### IP-1. `Scope` 는 한 곳에서만 만들어진다 (BR-145, C55)

```python
C55.scope_for(user) -> Scope        # 유일한 생성 지점
AuthenticatedUser.scope             # 프로퍼티 — 호출부가 조립하지 않는다
```

**막는 것**: 라우터가 늘 때마다 필터를 잊는 것.
**왜 RLS 가 아닌가**: PostgreSQL RLS 는 세션마다 `SET LOCAL` 이 필요하고, 이 구성은
`app`·`worker`·CLI·마이그레이션이 각각 다른 연결을 쓴다. **한 곳이라도 빠뜨리면
조용히 무력화**되고, 그 사실을 테스트로 잡기 어렵다.

### IP-2. 존재를 알려 주지 않는다 (BR-146)

남의 문서 id → **404**. 403 이 아니다.

**막는 것**: 문서 id 열거로 **다른 사용자가 무엇을 언제 올렸는지** 알아내는 것.
문서 id 는 연속된 정수다.

### IP-3. 세 겹 증명 (FQ7-8=a) ⭐

규칙을 적는 것과 그것이 지켜지는 것은 다르다. 이 프로젝트는 **"테스트는 초록불인데
그 경로가 한 번도 돈 적이 없다"로 결함 5건**(25·39·40·46·47)을 만들었다.

| 겹 | 무엇을 잡는가 | 한계 |
|---|---|---|
| ① 교차 접근 통합 테스트 | 두 계정 · 각자의 문서 · 실제로 새는지 | **테스트가 커버하는 경로만** |
| ② 정적 검사 — C55 밖 `Scope(` 금지 | **새 라우터가 규칙을 우회하는 것** | 실행 시 동작은 못 본다 |
| ③ 경로별 필터 단위 테스트 | 벡터·키워드·물질·이력 각각에 `owner_id` 가 걸리는가 | 조합은 못 본다 |

**②가 왜 필요한가**: 새 화면이 `Scope(owner_id=request.user.id)` 를 직접 만들어도
①은 통과한다 — 그 화면을 덮는 테스트가 아직 없기 때문이다. ②만 잡는다.

**테스트 데이터는 테스트가 만들고 테스트가 지운다**(FQ7-9=a). 공개 코퍼스에
`owner_id` 를 붙여 재사용하지 않는다 — **결함 48(통합 테스트가 실코퍼스 청크를
지웠다)·결함 53(기준선을 남겼다)과 같은 부류를 자초하는 일**이다.

## 5. 관측 패턴 (OP-1 ~ OP-2)

### OP-1. 이벤트만, 새 테이블 없음 (FQ7-10=a)

```
login_succeeded · login_failed · upload_accepted · upload_rejected(reason)
document_deleted · isolation_denied
```

**`isolation_denied` 를 넣는 이유**: 격리가 **실제로 막은 순간**을 볼 수 없으면
격리가 동작하는지 사후에 알 방법이 없다. 0건이 계속되는 것과 로그가 없는 것은
다르다.

**새 테이블을 만들지 않는 이유**: u4 가 `evaluation_run` 을 만든 것은 **비교라는
명확한 소비자**가 있었기 때문이다. 여기에는 그 소비자가 없다 — 운영 화면이 없는
상태의 메트릭 테이블은 쓰는 사람이 없다.

### OP-2. 마스킹 확장 (NFR-14, FQ7-11=a)

기존 규칙은 `password`·`token`·`authorization` 을 잡지만 **`Cookie: session=...`
은 못 잡는다 — 그 안에 JWT 가 통째로 들어 있다.**

추가:
| 대상 | 이유 |
|---|---|
| `cookie` · `set-cookie` | JWT 가 통째로 들어간다 |
| 이메일 | 비밀값은 아니지만 **실패 로그가 가입자 명단이 된다** |
| `$argon2id$…` | 유출돼도 즉시 위험하진 않지만 로그에 있을 이유가 없다 |

**확인 방법**: 실제 로그를 뽑아 눈으로 본다. "충분하다"를 확인 없이 주장하지 않는다.

## 6. 방어 심층도 요약

| 위협 | 1차 | 2차 | 3차 |
|---|---|---|---|
| 비밀번호 탈취 | argon2id | 정책(BR-133) | 로그 마스킹 |
| 무차별 대입 | 지수 백오프 | argon2 비용 | 정책 |
| 토큰 탈취 | HttpOnly | 12시간 만료 | — *(무효화 없음)* |
| CSRF | SameSite=Lax | CSRF 토큰 | — |
| 악성 업로드 | 내용 검증 5단계 | **실행하지 않는 구조** | 격리(폭발 반경) |
| 업로드 텍스트 인젝션 | u2 SP-3 이스케이프 | SP-4 색인 시 스캔 | 격리(본인 질의만) |
| 격리 실패 | `Scope` 단일 생성 | 정적 검사 | 교차 접근 테스트 |
| 디스크 고갈 | 파일당 20MB | 사용자당 200MB | — |
| 정보 노출 | 404 정책 | 실패 응답 동일화 | 로그 마스킹 |

**3차가 비어 있는 줄이 셋이다.** 토큰 무효화·CSRF·용량은 두 겹까지다 — 그것이
현재 수준이고, 채워진 것처럼 보이게 쓰지 않는다.

## 7. Build & Test 로 이월하는 검증

| 항목 | 방법 |
|---|---|
| 격리 ①②③ | IP-3 세 겹 전부 |
| 로그인 실패 응답 시간 | 존재/부재 계정의 응답 시간 분포 비교 |
| 업로드 거부 5종 | 확장자 위장·크기 초과·페이지 초과·`/OpenAction`·손상 파일 |
| 마스킹 | 실제 로그에 쿠키·이메일·해시가 남는지 눈으로 확인 |
| 볼륨·권한 | 컨테이너 안에서 `stat` — 비루트(NFR-30)·0700 |
| 공개 코퍼스 불변 | 계정 도입 후에도 78문서가 익명에게 그대로 보이는가 (BR-147) |
| u4 평가 불변 | `Scope(owner_id=None)` 고정 확인 (BR-148) |
