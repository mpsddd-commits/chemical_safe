# Frontend Components — u5-account-upload

**FR-46**(문서 관리 화면) · **FR-47**(질의 이력 화면) + 인증 화면

기존 화면과 같은 방식이다 — Jinja2 SSR, JS 프레임워크 없음, 자동 이스케이프 켜짐.

### P6 `/usage` 를 어떻게 할 것인가
u2 는 "u5 까지 `127.0.0.1` 바인딩이 유일한 통제"라고 적어 두었다. 이제 계정이
생기므로 **로그인 필수로 바꾼다.** 다만 이것은 운영 화면이고 역할 개념이 없으므로,
로그인한 아무나 전체 사용량을 본다 — **역할 기반 통제가 아니라는 것을 적어 둔다.**
FR 에 역할이 없으므로 만들지 않는다.

## P8. 로그인 · 가입 (FR-31, FR-33, FR-34)

```
┌─ 가입 ─────────────────────────────────┐
│ 이메일        [                      ] │
│ 비밀번호      [                      ] │
│   10자 이상, 영문 대/소문자·숫자·기호 중 3종
│                                         │
│ ☐ 아래 면책 고지를 읽고 동의합니다        │
│ ┌─────────────────────────────────────┐ │
│ │ 이 서비스는 화학물질 안전·규제 정보를  │ │
│ │ 참고용으로 제공합니다. 실제 취급·대응  │ │
│ │ 은 반드시 원문과 전문가 판단에 …      │ │
│ └─────────────────────────────────────┘ │
│           [ 가입 ]                      │
└─────────────────────────────────────────┘
```

- **동의 체크 없이는 가입 버튼이 동작하지 않는다**(BR-152). 서버에서도 다시 검증한다 —
  클라이언트 검증만 있으면 그것은 검증이 아니라 안내다
- 면책 문구 전문이 접히지 않은 채로 보인다. u2 의 BR-84(면책은 접히지 않는다)와 같다
- 로그인 실패 메시지는 **한 종류**: "이메일 또는 비밀번호가 올바르지 않습니다"(BR-134)
- 비밀번호는 어떤 화면에도 다시 표시되지 않고, 오류 시 폼에 되돌려 넣지 않는다

## P9. 문서 관리 (FR-27, FR-29, FR-46)

```
┌─ 내 문서 ───────────────────────────────────────────────────┐
│ [ 파일 선택 ]  PDF · 20MB 이하 · 200페이지 이하   [ 업로드 ] │
├──────────────────────────────────────────────────────────────┤
│ 파일명              크기    페이지  상태          │
│ 자사MSDS_황산.pdf   1.2MB   12     ✅ 색인 완료   [삭제][재색인]│
│ 공정안전자료.pdf    8.4MB   87     ⏳ 색인 중 62% │
│ 시험성적서.pdf      0.3MB    4     ⚠️ 구조화 실패 [삭제][재색인]│
└──────────────────────────────────────────────────────────────┘
```

- **여기 나오는 것은 내가 올린 문서뿐이다.** 공개 코퍼스 78문서는 나오지 않는다 —
  이 화면은 "검색 대상 전체"가 아니라 "내가 올린 것"이다
- 진행률은 u1 의 `job` 을 그대로 읽는다(FR-6). 새 진행률 체계를 만들지 않는다
- **"구조화 실패"를 숨기지 않는다.** u3 에서 MSDS PDF 8건 중 2건이 섹션 0으로
  끝났다 — 업로드에서도 일어날 일이고, 그때 카드·인용이 비는 이유가 여기 보여야 한다
- 거부된 업로드는 **왜 거부됐는지 그대로** 보여준다:
  ```
  ⛔ 업로드할 수 없습니다 — PDF 파일이 아닙니다 (매직 바이트 불일치)
  ⛔ 업로드할 수 없습니다 — 페이지 수 340 (한도 200)
  ⛔ 업로드할 수 없습니다 — 자동 실행 요소(/OpenAction)가 포함되어 있습니다
  ```
  "업로드 실패"만 보여주면 사용자는 파일을 고칠 수 없다
- 삭제는 **되돌릴 수 없다**(BR-144). 확인 단계를 둔다

## P10. 질의 이력 (FR-32, FR-47)

```
┌─ 질의 이력 ─────────────────────────────────────────────┐
│ 08-29 16:12  CAS 7664-93-9 물질 취급 시 보호구는?        │
│              → 답변 · 근거 2건                    [열기] │
│ 08-29 15:40  유해화학물질을 함께 보관해도 되나요?         │
│              → 근거 부족으로 답변하지 않음         [열기] │
└──────────────────────────────────────────────────────────┘
```

- 저장된 문장·인용·**스냅샷**으로 재열람한다(BR-149). 재실행 버튼 없음(BR-150)
- **거부된 질의도 이력에 남는다.** u2 가 `query_log` 에 결과를 기록하는 이유가
  이것이고(BR-78), "답하지 않았다"는 것도 사용자가 알아야 할 이력이다
- 인용된 청크가 재색인으로 사라졌으면 **스냅샷 본문을 보여주고 그렇게 표시한다** —
  BR-93 이 `SET NULL` 을 고른 이유가 여기서 값을 한다

## 공통

### 헤더
```
safeenv   질의  물질  |  내 문서  이력      [로그인]
                                          또는  user@x.com [로그아웃]
```
- 익명 상태에서 "내 문서·이력"은 **보이되 누르면 로그인 화면**으로 간다.
  숨기면 기능이 없는 줄 안다

### CSRF
상태를 바꾸는 폼(가입·로그인·업로드·삭제·재색인) 전부에 토큰을 넣고 서버가
검증한다(BR-138).

### 면책
u2 의 상시 표시(FR-35, BR-84)는 **그대로 둔다.** 가입 시 동의(FR-34)가 생겨도
답변 화면의 면책 문구는 계속 보인다 — 익명 사용자에게는 그것이 유일한 고지다.

### 에러 표시
`/documents/{남의 id}` 는 **404**(BR-146). "권한 없음"이 아니다 — 그 메시지는
문서가 존재한다는 사실을 알려 준다.
