## 실측 — u1·u2 가 깔아둔 것은 실제로 있다

설계 문서가 "스키마 변경이나 검색 시그니처 변경 없이 격리를 도입한다"고 적었다.
**확인했고, 사실이다.**

```sql
owner_id 컬럼이 있는 테이블:  document · chunk · query_log     (전부 항상 NULL)
```

```python
# indexing/vector_index.py — u1 이 이미 써 둔 것
def apply_scope(stmt, scope: Scope):
    """Public rows always; the caller's own rows in addition (FR-28 groundwork)."""
    if scope.owner_id is None:
        return stmt.where(ChunkRow.owner_id.is_(None))
    return stmt.where(
        (ChunkRow.owner_id.is_(None)) | (ChunkRow.owner_id == scope.owner_id)
    )
```

```python
# core/types.py — DD-19
class Scope:
    """A REQUIRED argument on every search method."""
    owner_id: int | None = None
```

**FR-28(소유자 격리)의 질의 경로는 이미 구현되어 있다.** u5 가 할 일은 `owner_id` 에
**값을 넣는 것**이지 격리 로직을 만드는 것이 아니다. 색인 경로도
`replace_for_document(..., owner_id=owner_id)` 로 이미 인자를 받는다.

> u4 에서 `RetrievalConfig` 는 문서에만 있고 코드에 없었다. 이번에는 반대다 —
> **문서가 약속한 것이 실제로 있다.** 확인하고 시작하는 이유가 이것이다.

## 실측 — 없는 것

| 없는 것 | 의미 |
|---|---|
| **인증 코드·의존성 0** | `jwt`·`bcrypt`·`argon2`·`passlib` 어느 것도 `pyproject.toml` 에 없다. u2 의 `google-genai` 이후 **첫 신규 런타임 의존성**이 된다 |
| **사용자 테이블 0** | `user_account` 신설 필요 |
| **FR-34 동의 기록** | u2 는 면책 문구를 **항상 표시**하는 절반(FR-35, BR-84)만 구현했다. **"1회 동의하고 그 기록을 저장한다"는 절반은 계정이 없어 미구현**이다 — 이 유닛에서 닫힌다 |
| **업로드 경로 0** | `originals_dir=/data/originals` 는 수집 원본용(BR-44)이다. 업로드는 별도 |
| **라우터의 인증 훅 0** | `get_session()` 만 있고 `get_current_user()` 에 해당하는 것이 없다 |

## 이 유닛이 건드리는 기존 코퍼스의 상태

```
문서 78 / 청크 1,633   전부 owner_id IS NULL (= 공개 코퍼스)
질의 이력 query_log      owner_id 전부 NULL (익명 질의)
```

**기존 데이터는 전부 공개다.** 계정을 도입해도 이 문서들은 계속 모두에게 보여야 한다 —
`apply_scope` 가 `owner_id IS NULL` 을 항상 포함하는 이유다.
