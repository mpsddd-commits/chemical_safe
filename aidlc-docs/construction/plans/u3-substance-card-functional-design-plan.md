## 🔴 선행 조건 — 결함 40

**물질 마스터에 쓰는 코드가 존재하지 않는다.**

```
SubstanceRepo.upsert()       호출부 0
SubstanceRepo.add_synonyms() 호출부 0
substance / substance_synonym / document_substance   전부 0행
```

BR-33(물질 저장)·BR-37(문서↔물질 연결)은 **u1 규칙**이고 FR-1 로 추적되는데
구현된 적이 없다. `SubstanceRepo` 와 스키마는 있고 **쓰기 경로만 없다.**

u1 Build & Test 는 `stats.substances = 0` 을 보고 통과했다 — **0 이 "아직 수집
안 함"으로 읽혔지 "수집해도 마스터가 안 채워짐"으로 읽히지 않았다.**

**재수집은 필요 없다.** 원본 40건이 보존되어 있다(BR-44).

## 실측 데이터 — 이 유닛이 실제로 가진 재료

### 물질 API 원본 40건 (`data/originals/ncis_substance/*.json`)

| 필드 | 보유 | 카드에서의 쓰임 |
|---|---|---|
| `cas_number` | **40/40** | 조회 키, BR-33 충족 |
| `name_ko` · `name_en` | **40/40** | 조회 키, 동의어 |
| `symptom` | 40/40 | 증상 |
| `inhale` · `skin` · `eyeball` · `oral` | 40 / 40 / 40 / 39 | **노출경로별 응급조치** |
| `etc` | 40/40 | 기타 |

**GHS 분류 · 신호어 · H·P 문구 · 물리화학적 성질 · 적용법령 필드는 없다.**

### MSDS 문서 — 섹션 라벨 실측

`msds_01` ~ `msds_16` 각 **6~7건**. 즉 16섹션 구조를 갖춘 MSDS 는 **약 7건**이다.

### ⚠️ 여기서 나오는 사실

FR-24 가 요구하는 7개 항목의 출처는 대부분 **MSDS 섹션**인데:

| 카드 항목 | 출처 | 커버리지 |
|---|---|---|
| GHS 분류·신호어 | MSDS 2 | ~7 물질 |
| H·P 문구 | MSDS 2 | ~7 물질 |
| 물리화학적 성질 | MSDS 9 | ~7 물질 |
| 권장 개인보호구 | MSDS 8 | ~7 물질 |
| 응급조치 | MSDS 4 **+ 물질 API 노출경로 4필드** | ~7 + **40** |
| 저장·취급 주의 | MSDS 7 | ~7 물질 |
| 적용 법령 | MSDS 15 + `law` 문서 | ~7 물질 |

**물질 40건 중 대부분은 MSDS 가 없다.** 즉 대부분의 카드는 항목 대부분이
"정보 없음"이 된다.

이것은 결함이 아니라 **FR-25 가 정확히 예상한 상황**이다 — "데이터가 없는 항목은
추정하지 않고 정보 없음으로 표시한다". 설계가 이 경우를 위해 쓰였다.
다만 **시연할 때 무엇이 보이는지**는 설계 결정이 필요하다(FQ4-8).

# 2부. 설계 질문 (FQ4-1 ~ FQ4-14)

## A. 결함 40 — 물질 마스터를 어떻게 채우나

### FQ4-1
**마스터 투영은 어디서 일어나나?**

A) **u1 색인 경로에 투영 단계를 추가한다** — `IndexingService` 가 `ncis_substance`
   문서를 색인할 때 `SubstanceRepo.upsert()` 도 호출한다
   *(권장 — BR-33·BR-37 은 u1 규칙이고 FR-1 로 추적된다. 원래 있어야 했던 자리다.
   u3 에 두면 "u1 이 수집한 것을 u3 이 뒤늦게 정리한다"는 구조가 되어 다음 수집에서
   같은 구멍이 다시 생긴다)*

B) u3 에 별도 백필 명령만 만든다 — u1 은 건드리지 않는다

C) 둘 다 — u1 에 투영 추가 + u3 에 백필 명령

[Answer]: A

### FQ4-2
**기존 코퍼스(이미 색인된 40건)는 어떻게 채우나?**

A) **재색인 1회** — BR-44 보존 원본에서 투영. 소스 재호출 없음
   *(권장 — BR-20a·BR-31a·BR-27a·N3 스캐너가 전부 이 경로로 배포됐다. 검증된 경로다.
   약 35분)*

B) 전용 백필 명령 — 색인은 건드리지 않고 마스터만 채운다 (빠르지만 경로가 하나 늘어난다)

[Answer]: A

### FQ4-3
**동의어(`substance_synonym`)는 무엇으로 채우나?**

원본에 **이명(異名) 필드가 없다.** `name_ko` · `name_en` 뿐이다.

A) **`name_ko` · `name_en` 두 개만 등록하고, 이명은 없다는 사실을 기록한다**
   *(권장 — NFR-8. 없는 데이터를 만들지 않는다. FR-26 이 요구하는 5종 중
   국문·영문·CAS·UN 은 충족되고 **이명만 미충족**이며, 그 사실을 명시한다)*

B) 규칙으로 변형을 생성한다 (공백 제거, 하이픈 변형 등)

C) 외부 이명 사전을 도입한다 — 새 소스, 새 수집 경로

[Answer]: A

> **B 의 위험**: 생성된 변형은 "이명"이 아니라 우리가 만든 문자열이다.
> `substance_synonym.term_type` 이 그것을 실제 이명과 구분하지 못하면,
> 카드가 근거 없는 이름을 사실처럼 보여준다.

## B. 카드 조립

### FQ4-4
**한 항목에 여러 출처가 있을 때 무엇을 보여주나?**

A) **가장 신뢰도 높은 출처 1건** — MSDS > 물질 API > 법령 순
B) **모든 출처를 나열한다** *(권장 — 안전 정보에서 "다른 문서는 뭐라고 하는가"가
   중요하다. 특히 값이 서로 다르면 그것 자체가 사용자가 알아야 할 정보다)*
C) 값이 같으면 하나로, 다르면 모두 표시

[Answer]: B

### FQ4-5
**항목별 출처 표기를 u2 의 무엇으로 하나?**

A) **u2 의 표기 규약(문서 제목 + 섹션 라벨 + 원문 링크)을 재사용하되,
   `citation_snapshot` 은 쓰지 않는다** *(권장 — 스냅샷은 "답변이 인용한 시점을
   동결"하는 장치다(BR-92). 카드는 답변이 아니라 **현재 상태 조회**이므로 항상
   최신을 보여주는 것이 맞고, 동결하면 오히려 낡은 안전 정보를 보여준다)*

B) `citation_snapshot` 도 함께 남긴다 — 조회 시점을 동결

[Answer]: A

### FQ4-6
**이름 검색이 여러 물질에 걸리면?**

A) **후보 목록을 보여주고 사용자가 고른다** *(권장 — 안전 정보에서 잘못된 물질을
   자동 선택하는 것은 R-6 다. "황산"과 "황산구리"를 시스템이 골라서는 안 된다)*
B) 가장 잘 맞는 하나를 보여준다
C) CAS 완전일치만 단일 결과, 이름은 항상 목록

[Answer]: A

### FQ4-7
**응급조치 항목은 물질 API 의 노출경로 4필드를 어떻게 쓰나?**

A) **`inhale`·`skin`·`eyeball`·`oral` 을 노출경로별 하위 항목으로 그대로 노출한다**
   *(권장 — 40건 전부가 갖고 있는 유일한 실질 데이터다. MSDS 4번 섹션이 있으면
   함께 보여준다(FQ4-4=B))*
B) 하나의 "응급조치" 텍스트로 합친다

[Answer]: A

### FQ4-8
**MSDS 가 없어 항목 대부분이 비는 카드는 어떻게 보이나?**

A) **모든 항목을 표시하되 없는 것은 "정보 없음"으로 채우고, 카드 상단에
   "이 물질은 MSDS 문서가 없어 N개 항목이 비어 있습니다"를 고지한다**
   *(권장 — FR-25 준수. 그리고 빈 항목을 감추면 카드가 완전해 보인다. u2 의
   BR-88(제거된 문장 개수 표시)과 같은 원칙)*

B) 값이 있는 항목만 표시한다 — 카드가 짧고 깔끔해진다

C) MSDS 가 없으면 카드를 만들지 않고 "정보 부족"으로 거부한다

[Answer]: A

> **B 의 문제**: 사용자는 "이 물질은 보호구 정보가 없다"와 "이 시스템이 보호구
> 항목을 안 보여준다"를 구분할 수 없다.
> **C 의 문제**: 40건 중 33건이 카드를 못 갖는다. 응급조치 데이터는 있는데도.

## C. 조회·성능

### FQ4-9
**조회 키 정규화는?**

A) **u1 `normalize()` + CAS/UN 정규식을 재사용한다** *(권장 — 색인과 조회가 같은
   정규화를 써야 한다. BR-63 이 u2 에서 정한 것과 같은 이유)*
B) 카드 전용 정규화를 만든다

### FQ4-10
**NFR-3(P95 ≤ 1초)를 어떻게 만족하나?**

   *(권장 — u2 실측에서 순수 DB 경로는 26ms 였다. 1초는 넉넉하다)*
B) 카드를 미리 조립해 캐시한다

[Answer]: A

### FQ4-11
**UN 번호 조회는?**

원본에 `un_number` 필드가 **없다.** 스키마 컬럼은 u1 이 만들어 두었다.

A) **컬럼은 유지하되 항상 NULL 이고, UN 조회는 "데이터 없음"으로 답한다.
   그 사실을 카드와 문서에 명시한다** *(권장 — FR-26 의 5종 중 UN 미충족을
   숨기지 않는다)*
B) UN 조회를 지원 목록에서 제거한다

[Answer]: A
