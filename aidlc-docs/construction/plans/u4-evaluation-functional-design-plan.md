## 🔴 이 유닛의 지배적 제약 — 무료 티어

**이것이 u4 설계의 중심이다.** u1~u3 에서는 배경이었지만 여기서는 실행 가능성 자체를
결정한다.

### 실측 — 질의 1건이 쓰는 LLM 호출 수

`llm_call` 테이블 전수 (2026-08-27):

| 결과 | 질의 수 | 질의당 LLM 호출 |
|---|---|---|
| `answered` | 15 | **5.25** |
| `answered_partial` | 3 | 5.44 |
| `refused_unsupported` | 3 | 5.18 |
| **`refused_low_relevance`** | 33 | **0.03** |

답변형 1건 = 생성 1 + 문장별 검증 ~4 (BR-86a: `1 + 문장수`).
**거부형은 사실상 0** — 1단계 거부는 LLM 을 부르기 전에 결정된다(BR-73).

### 산수

```
무료 티어  모델당 하루 20 요청  (GenerateRequestsPerDayPerProjectPerModel)

FR-36 이 요구하는 30~50문항 중 답변형이 30건이라면
   30 × 5.25 ≈ 158 호출  →  20/일 기준 8일
여기에 FR-38 LLM 심판 30 호출이 더 붙는다
```

**한 번의 전체 평가에 8일 이상 걸린다.** 이것은 튜닝으로 줄일 수 있는 값이 아니라
구조다. 오늘 이미 11/20 을 썼다.

### 다만 — LLM 이 필요 없는 지표가 절반이다

| 지표 | LLM 호출 | 근거 |
|---|---|---|
| **Recall@k** | **0** | 검색 결과와 정답 근거를 대조할 뿐 |
| **MRR** | **0** | 위와 같음 |
| **거부 정확도** | **0** | 1단계 거부는 LLM 이전에 결정된다 |
| 정답률 | 필요 | 답변이 있어야 한다 |
| 인용 정확도 | 필요 | 답변 문장의 인용을 본다 |
| 충실도(FR-38) | 필요 | 심판 호출 |

**검색 지표와 거부 정확도는 30~50문항 전체를 매일, 몇 초 만에, 무료로 돌릴 수 있다.**
u2 에서 결함 27(RRF 를 임계값으로 읽음)·결함 45(완전일치를 코사인이 뒤집음)를 잡아낸
것이 바로 이 계층이었다는 점이 근거다 — 품질 회귀의 상당수는 LLM 앞단에서 생긴다.

### FQ5-3. 정답 근거를 어느 단위로 적는가

- **(a)** **문서 + 섹션코드** — `{document: "화학물질관리법", section: "제13조"}` *(권장)*

- **(d)** 자유 텍스트 키워드

> 그 유형은 문서 단위로 적어야 한다 — 로더가 둘 다 받아야 한다.
