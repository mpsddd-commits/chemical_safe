# Operations — safeenv

**단계**: 🟡 OPERATIONS (PLACEHOLDER — 실행 계획대로)
**작성일**: 2026-08-30
**선행**: CONSTRUCTION 5/5 완료 (u1~u5 전부 승인)

실행 계획은 이 단계를 "향후 배포·모니터링 워크플로용 자리표시자. 본 프로젝트에서는
**운영 문서 색인 역할**"로 정의했다. 이 문서가 그 색인이며, 다섯 유닛에 흩어진
운영 정보를 한 곳에 모은다. **새 설계를 하지 않는다** — 여기 있는 모든 숫자와
규칙은 각 유닛에서 실측되고 승인된 것이다.

### 승격된 기준선 (u4)

| 실행 | 모드 | 코퍼스 | Recall@5 | MRR | 정답률 | 인용 정확도 | 충실도 | 거부 정확도 |

| **385** | `retrieval_only` | 82 / 1,712 | **0.967** | **0.766** | — | — | — | **1.000** |
| **276** | `full` | 82 / 1,712 | 0.867 | 0.630 | **0.917** | 0.610 | 0.958 | 0.400 |

같은 코퍼스(1,712)·같은 골든셋. 검색 지표 차이는 코드(조문 제목 층)만의 차이라

모드당 하나다. 검색전용은 73 → 127 → 219 → **240**(BR-65a 반영), full 은
10 → **221**. 두 기준선 모두 현 코퍼스(82/1,697)와 코드 정체를 가지며
`incomparable` 없이 판정된다.

주의해 읽을 것: 정답률 0.792 → 0.870 은 코퍼스가 함께 바뀌어 원인 분해가 안 된다.

모드마다 기준선이 따로 있다(결함 55). 검색전용 실행을 `full` 기준선과 비교하면

## 2. 매일 / 주기 작업

| 주기 | 명령 | 비용 | 무엇을 지키는가 |
|---|---|---|---|
| **매일** | `evaluate --retrieval-only` | LLM 0, 수초 | 검색 회귀. u2 결함 27·45 가 이 계층에서 생겼다 |
| 필요 시 | `evaluate --full` → `--resume` | 심판 20/일 → **2일** | 정답률·인용·충실도 |

| **코드 변경 후** | `docker compose up -d --build app worker` | 빌드 수분 | **재빌드만으로는 안 바뀐다.** 컨테이너 재생성까지. 잊으면 통합 테스트와 승격이 막는다 (결함 58) |

| 규칙 변경 시 | `reindex --scope all` | **약 35분** | 청킹·구조화 규칙 반영 |
| `down -v` 전 | `scripts/backup.sh` | — | 초기 색인이 최대 8시간이다(NFR-4) |

### 배포가 최신인지 확인하는 법 (결함 58)

```bash
docker compose exec app python -m app.cli stats | tail -1   # build: 1353cb2a38c0
python -c "from app.core.build import build_id; print(build_id())"
curl -s http://127.0.0.1:8300/healthz                       # "build" 필드
```
세 값이 같아야 한다. `build` 는 이미지에 구워 넣은 스탬프가 아니라 **디스크에 있는
파일을 그 자리에서 해싱한 값**이다(`app/core/build.py`). 스탬프는 그 자체로 낡을 수
있고, 결함 58 은 낡은 것이 자신 있게 답한 사고였다.

대상은 Dockerfile 이 `COPY` 하는 여섯 항목뿐이다 —
`app` `config` `migrations` `prompts` `eval` `pyproject.toml`.
`tests/` `data/` `logs/` 는 이미지에 없으므로 세지 않는다.

**확인은 잊어도 된다.** 어긋나면 세 곳에서 저절로 걸린다:
- 통합 테스트 `test_deployed_code_is_current` 가 **실패**한다
- `evaluate --promote` 가 **거부**한다 (종료코드 3)
- `evaluate --list` 의 코드 열에 `현재` 표시가 사라진다

### 작업 디렉터리 (2026-09-02 이전)

작업·Docker·데이터는 **`chemical_safe/`** 다. 이전의 `safeenv/` 는 백업으로
남아 있으나 스택이 가리키지 않는다. compose 프로젝트 이름이 `safeenv` 로
고정돼 있어 컨테이너·볼륨 이름은 그대로이고, **DB(명명 볼륨)는 이전을 그대로
넘겼다** — 문서 82 · 청크 1,712 · 기준선 2개 · 진행 중이던 실행 387 전부 보존.

이전한 이유는 CI 다. 깃 저장소가 작업 트리와 다르면 **CI 가 실제로 도는 코드가
아닌 것을 검사한다** — 결함 58 과 같은 모양이다.

> 이전 중에 `cd` 를 빠뜨려 한 번 옛 경로에서 기동했다. `docker inspect` 의
> 바인드 마운트 경로로 확인해서 잡았다. **명령이 무엇을 했다고 말하는 것과
> 실제로 한 것은 다르다.**

### CI (GitHub Actions)

```
.github/workflows/ci.yml       push·PR 마다 — ruff + 단위 테스트, 약 1분
.github/workflows/docker.yml   main push 시 Dockerfile 빌드 확인 (5~10분)
```

**통합 테스트와 평가 하네스는 일부러 CI 에 없다.** 실제 코퍼스를 전제하므로
CI 에서 채우려면 재색인 35분 + 임베딩 모델 2GB 가 매 실행마다 필요하다.
그 둘은 로컬에서 돌린다(아래).

CI 는 `ml` 엑스트라를 설치하지 않는다 — NFR-28 대로 단위 테스트가 모델에 닿지
않으므로 없이도 전부 통과한다(실측: 깨끗한 venv 에서 677 통과 / 10초).
**깨끗한 환경이 개발 호스트보다 하나 더 돌린다**: 호스트에 `arq` 가 없어
`importorskip` 으로 건너뛰던 테스트가 CI 에서는 실행된다.

`pip install -e .` 는 쓰지 않는다 — 최상위 디렉터리가 여럿이라 setuptools
자동 탐색이 실패한다. Dockerfile 과 같이 의존성만 설치하고 pytest 를 루트에서
돌린다.

### 테스트를 돌리는 법
```bash
python -m ruff check app/ tests/ migrations/        # migrations 포함. 빠뜨리면 안 보인다
python -m pytest tests/unit -q                      # 641 + 1 스킵. 환경 불필요
set -a; . ./.env; set +a                            # 통합은 이 export 가 필수다
POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=5433 REDIS_HOST=127.0.0.1   python -m pytest tests/integration -m integration -q    # 60 + 1 스킵
```
통합 실행에는 **배포 최신성 검사 3건이 들어 있다**(`test_deployed_code_is_current`).
코드를 고치고 컨테이너를 재생성하지 않았으면 여기서 붉어진다.
**통합 테스트는 호스트에서 돈다.** `app` 이미지에는 dev 의존성이 없어 `pytest` 가
설치돼 있지 않다. 포트 5433 은 `docker-compose.override.yml` 이 여는 것이다(ID-12 에
따라 메인 compose 는 DB 포트를 게시하지 않는다).

`.env` export 를 빠뜨리면 **전건 인증 실패**한다. `tests/conftest.py` 가 단위 실행을
환경 없이 돌리려고 `POSTGRES_PASSWORD=test-password` 를 넣어 두는데,
pydantic-settings 에서는 `os.environ` 이 `.env` 를 이긴다.

### 재색인 전에는 반드시
**35분짜리 재색인을 가설 검증에 쓰지 않는다.** u1 에서 두 번 낭비하고 배운 것이고,
결함 47 에서는 시작한 재색인을 20/79 에서 중단해 그 규칙이 값을 했다.
청킹·연결 규칙을 바꿨으면 **전 코퍼스 건식 시뮬레이션을 먼저** 돌린다.

## 3. 기동에 필요한 것

```bash
docker compose up -d          # NFR-29, 단일 명령
```

| 환경변수 | 없으면 |
|---|---|
| `POSTGRES_PASSWORD` | DB 를 쓰는 프로세스가 **기동 실패** |
| **`JWT_SECRET`** (32자 이상) | **앱이 기동 실패** (BR-137). CLI·워커는 무관 |
| `GEMINI_API_KEY` | 앱은 뜨고 **질의만** 불가 (BR-02) |
| `NCIS_API_KEY` 등 3종 | 앱은 뜨고 **해당 소스 수집만** 불가 |

**비밀키에 기본값을 두지 않는다.** 개발용 기본값은 배포까지 따라가고, 기본값이 있는
비밀키는 비밀이 아니다.

```bash
python -c "import secrets; print('JWT_SECRET=' + secrets.token_urlsafe(48))" >> .env
```
값을 화면에 찍지 말 것 (NFR-14).

## 5. 자주 나는 실패와 원인

| 증상 | 원인 | 대응 |
|---|---|---|
| 업로드 후 "⛔ 색인 실패 — PDF produced no usable text" | 스캔 PDF. 텍스트가 없다 | 정상 동작. 텍스트 PDF 로 다시 |
| 카드가 6/7 결측 | 그 물질의 MSDS 가 코퍼스에 없다 | 정상. MSDS 추가 수집이 유일한 해결 |
| 황산 GHS·톨루엔 물리화학 결측 | 문서 20·24 가 구조화 실패(섹션 0) | R-2. PDF 파싱 한계 |
| `evaluate` 가 `incomparable` | 코퍼스·모델·프롬프트가 기준선과 다르다 | 정상. 다른 것을 잰 두 수를 빼지 않는다 |
| `evaluate` 종료코드 4 | 할당량 소진 | **실패가 아니다.** `--resume <id>` |
| 질의가 429 | 무료 티어 | 대기. 하루 ~3질의(답변 모델 기준) |
| 로그인이 2초씩 걸린다 | 연속 실패 후 백오프 | 정상(AP-2). 올바른 비밀번호로 즉시 복구 |
| 로그에 `unknown_doc_type` | 컨테이너가 구 이미지다. 코드에 그 타입이 없다 | `docker compose up -d --build app worker` (결함 58) |
| 같은 코퍼스인데 지표가 다르다 | 위와 같다. 코드가 두 벌 돌고 있다 | `stats` 의 `build` 를 호스트와 대조 |
| `evaluate --promote` 가 종료코드 3 | 그 실행을 낸 코드가 지금 도는 코드가 아니다 | 재생성 → 재측정 → 승격. `--full` 이면 `--accept-stale` |
| 통합 테스트 `test_deployed_code_is_current` 실패 | 배포가 작업 트리보다 낡다 | `docker compose up -d --build app worker` |

## 6. 보안 운영

| 항목 | 상태 |
|---|---|
| 비밀번호 | argon2id. 평문·가역 저장 없음 |
| 토큰 | HttpOnly · SameSite=Lax 쿠키, 12시간 |
| 업로드 | 웹 루트 밖 `/data/uploads/{owner}/{uuid}.pdf`, **700 appuser** |
| 격리 | 서비스가 `Scope` 를 만들고 C55 밖 생성은 **정적 테스트가 금지** |
| 로그 | 쿠키·이메일·argon2 해시·JWT **0건** (실 파일 확인) |
| 컨테이너 | 비루트(NFR-30), 워커는 `/data/uploads` 읽기 전용 |

### 무엇을 막지 못하는가 — 알고 운영한다
- **업로드 검증은 안티바이러스가 아니다.** 시그니처를 탐지하지 않고, 새 `pypdf`
  취약점을 막지 못한다. 실효 방어는 **파일을 실행하지 않고 텍스트만 추출**하는 구조다
- **백오프는 무차별 대입을 늦출 뿐 막지 않는다**
- **로그인 응답 시간이 완전히 같지는 않다** (존재 97.5ms / 없음 89.0ms)
- **로그아웃해도 이미 복사된 토큰은 만료까지 산다**

### 격리가 도는지 확인하는 법
```bash
docker compose exec -T app grep -c isolation_denied /logs/safeenv.log
```
**0건과 로그 없음은 밖에서 구분되지 않는다.** 이 이벤트가 기록된다는 것 자체가
격리가 살아 있다는 증거다.

## 7. 백업·복구

```bash
scripts/backup.sh     # docker compose down -v 전에 반드시
scripts/restore.sh <dump>
```

볼륨 3개가 상태를 갖는다: `safeenv_pgdata`(DB) · `safeenv_models`(임베딩 모델 4.3GB) ·
`safeenv_uploads`(사용자 파일). `data/originals/` 는 호스트 바인드이고 **BR-44 의
보관 원본**이라 재색인의 전제다.
