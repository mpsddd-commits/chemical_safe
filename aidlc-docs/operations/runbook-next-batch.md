## 1. 왜 하루에 안 끝나는가

심판 모델(`gemini-3.6-flash`) 무료 티어가 **하루 20콜**인데 30문항 완주에
**25콜**이 든다. 구조적으로 이틀이다. 초기화 창은 **13:40~16:10** 사이 어딘가로
실측돼 있고 정확한 시각은 모른다.

**할당량 소진은 실패가 아니다(BR-118).** `partial` 로 남고 다음 날 이어붙인다.

## 2. 이어서 돌리는 법 — 명령 하나

```bash
bash scripts/resume_and_promote.sh 609
```

`--no-promote` 를 **붙이지 않는다**. 완주하면 그대로 승격하라는 지시가 있다.

스크립트가 알아서 하는 것:
- 컨테이너·작업트리·**실행 609** 세 지문이 같은지 확인 (결함 58). 다르면 중단한다 —
  이어붙이는 것이 두 코드의 결과를 한 실행에 섞는 일이기 때문이다.
- 할당량 소진이면 1800초 대기 후 재시도, 최대 4회. 인프라 장애와 할당량을 구별한다.
- 완주하면 승격하고, 이어서 `--retrieval-only` 로 재현 확인까지 한다.

**재현 확인에서 전 지표가 `+0.000` 이어야 한다.** 아니면 승격한 기준선을 배포된
코드가 재현하지 못한다는 뜻이고, 그 기준선은 가드로 쓸 수 없다.

## 3. 완주할 때까지 하지 말 것

```
app/  config/  migrations/  prompts/  eval/  pyproject.toml
```

이 경로를 고치면 빌드 지문이 바뀌고, `promote_baseline` 이 **거부한다**. 이틀치
심판 할당량을 쓴 실행이 승격 직전에 막힌다.

지문을 바꾸지 않는 일은 해도 된다: `aidlc-docs/`, `README.md`, `tests/`,
`scripts/`, `docker-compose.yml`, `data/`.

`--accept-stale` 로 넘길 수는 있지만 그것은 "재현되지 않는 값을 기준선으로
삼는다"는 선언이다. 쓰면 실행 note 에 그 사실이 남는다.
